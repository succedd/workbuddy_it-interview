# Cloudflare Worker 后端部署指南

本站自带一个后端（`cloudflare/worker.js`），部署后提供两类能力：

1. **访问统计** —— 全局访问计数、当日访问、访客国家地理分布、热门城市、热门题目榜
2. **账号与云同步** —— 注册 / 登录 / 改密、个人学习数据云同步（收藏、错题、进度、周报）、题目投稿 + AI 质检

存储用两套 Cloudflare 免费资源：**KV**（统计计数）与 **D1**（SQLite，用户 / 投稿 / 限流表）。
**免费额度完全够用**（Worker 10 万请求/天、KV 10 万读/1 千写/天、D1 500 万行读/天）。

> ⚠️ **只建 KV 不建 D1，登录 / 注册 / 云同步会直接报错** —— 这是最常见的部署事故。

## 前置条件

- 一个 Cloudflare 免费账号（https://dash.cloudflare.com/sign-up）
- 本机安装 Node.js（≥16）

## 部署步骤

### 1. 安装 wrangler CLI

```bash
npm install -g wrangler
```

### 2. 登录 Cloudflare

```bash
wrangler login
```

浏览器会弹出授权页面，点 Allow 即可。

### 3. 创建 KV 命名空间（访问计数）

```bash
wrangler kv namespace create STATS
```

命令输出中会有一行 `id = "xxxxxxxxxxxx"`，复制这个 id。

### 3.5 创建 D1 数据库（用户与投稿）⚠️ 别漏

```bash
wrangler d1 create it-interview-users
```

输出里的 `database_id` 要填进 `wrangler.toml`。然后执行建表语句（`cloudflare/schema.sql`）：

```bash
wrangler d1 execute it-interview-users --file schema.sql --remote
```

> 想去掉 `--remote` 可在本地库上试；**正式环境必须带 `--remote`**，否则线上表仍是空的。
> Worker 首次请求时也会自愈建表（`ensureSubmitTables`），但那只覆盖投稿相关的表，
> `users` 等核心表仍建议按上面这条先建好。

### 4. 回填 wrangler.toml

打开本目录下的 `wrangler.toml`，把两处 id 换成上两步拿到的真实值：

```toml
name = "it-interview-stats"
main = "worker.js"
compatibility_date = "2024-09-23"

[[kv_namespaces]]
binding = "STATS"
id = "你的真实KV_ID"

[[d1_databases]]
binding = "USERS"
database_name = "it-interview-users"
database_id = "你的真实D1_ID"
```

### 4.5 环境变量（可选，但有两个「设错就静默失效」的要盯住）

后台 → Workers → `it-interview-stats` → Settings → Variables：

| 变量 | 类型 | 用途 | 不设时的行为 |
|---|---|---|---|
| `ADMIN_EMAIL` | Secret | 管理员邮箱（投稿审核权限） | 无管理员 |
| `DEEPSEEK_API_KEY` | Secret | AI 投稿质检 | 质检接口返回 `no_api_key` |
| `SITE_ORIGIN` | Plain | 站点地址，服务端回读 `/data/published.json` 用 | 用代码里的常量 |
| `ALLOWED_ORIGIN` | Plain | CORS 白名单，逗号分隔 | 用代码里的默认三域 |

> 🔴 **这两个是可选的「覆盖项」，一旦设了又忘了随换域名更新，故障是静默的**：
> `ALLOWED_ORIGIN` 设错 → 登录 / 云同步报跨域失败；
> `SITE_ORIGIN` 设错 → 分类快照恒为空串、AI 质检拿不到技术体系上下文（被 try/catch 吞掉，很难发现）。
> **换域名后请一并核对这两处。** 当前线上**均未设置**（走代码常量），是安全状态。

### 5. 部署 Worker

```bash
cd cloudflare
wrangler deploy
```

部署成功后终端会输出 Worker 地址，形如：

```
https://it-interview-stats.<你的子域名>.workers.dev
```

### 6. 前端接入

1. 打开 https://itinterview.com.cn
2. 进入管理后台 → 系统设置 → **Cloudflare Worker** 板块
3. 在「Worker 接口地址」填入完整 URL（如 `https://it-interview-stats.xxx.workers.dev`）
4. 保存后即生效——访客每次打开站点自动上报 `/visit`，浏览题目自动上报 `/view?id=题目ID`

## 验证

统计接口：浏览器访问 `https://你的worker地址/stats`，应返回 JSON：


```json
{
  "total": 123,
  "today": 45,
  "countries": {"CN": 40, "US": 5},
  "cities": {"北京": 20, "上海": 15},
  "topQuestions": [{"id": 1, "title": "...", "views": 30}]

```

## 接口说明

| 端点 | 方法 | 说明 |
|------|------|------|
| `/visit` | POST | 上报一次访问（自动识别国家/城市） |
| `/view?id=123` | POST | 上报题目浏览（id 为题目 ID） |
| `/stats` | GET | 获取全部统计数据（JSON） |
| `/auth/register` | POST | 注册 |
| `/auth/login` | POST | 登录 |
| `/auth/logout` | POST | 登出 |
| `/auth/me` | GET | 当前登录用户 |
| `/auth/password` | POST | 修改密码 |
| `/me/data` | GET / PUT | 读取 / 覆盖个人学习数据（云同步） |
| `/me/reports` | GET / POST | 周报列表 / 保存周报 |
| `/submit` | POST | 题目投稿（含 AI 质检 + IP 限流） |
| `/me/submissions` | GET | 我的投稿 |
| `/admin/users` | GET | 用户列表（管理员） |
| `/admin/submissions` | GET | 投稿列表（管理员） |
| `/admin/groups` | GET / POST | 投稿分组查询 / 创建（管理员） |

- **CORS 是白名单制，不是 `*`** —— 只有 `cloudflare/worker.js` 里 `resolveCorsOrigin()` 列出的来源才会回
  `Access-Control-Allow-Origin`。当前白名单 = `https://itinterview.com.cn`、`https://www.itinterview.com.cn`、
  `https://it-interview-889.pages.dev`；**其他任何域名一律不发放 ACAO**。
  🔴 **换域名时必须同步这张表**（或用环境变量 `ALLOWED_ORIGIN` 覆盖并重新 deploy），
  否则登录 / 注册 / 云同步会报跨域失败 —— 页面照常打开，**故障是静默的**。
- 数据存 Cloudflare KV（统计）+ D1（用户与投稿），全球边缘读写、无需自建数据库。

> 前端并不直接把上面这些路径拼在本站域名下，而是**先拉 `api-endpoints.json` 选一个入口**，
> 再在其上拼 `/auth/login` 等。所以要换后端地址，改 `api-endpoints.json` 即可，无需发版。

## 与百度统计的关系

两者并存互补：
- **百度统计**：地域/来源/趋势/用户行为分析
- **本 Worker**：全站累计访问数 + 跨访客热门题目榜（百度统计做不到按题目聚合）

## 常见问题

**Q: 部署后 /stats 返回全 0？**
A: 正常——KV 里还没有数据，等有访客触发 `/visit` 后就会有计数。

**Q: 想停用统计？**
A: 站点设置页清空 Worker 接口地址即可，前端不再上报；Worker 本身可保留或 `wrangler delete` 删除。

**Q: 免费额度会超吗？**
A: 10 万请求/天对个人题库站绰绰有余；真超了 Cloudflare 也不会断服务，只是有少量费用（极少见）。
