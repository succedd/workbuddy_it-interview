并查集的路径压缩和按秩合并为什么能把复杂度降到接近 O(1)？如何用它判断连通分量和环？

中级编程题算法工程师后端开发工程师并查集路径压缩按秩合并连通分量

题目

考察并查集的两个优化、均摊复杂度和图论中的典型应用。

参考答案

基本操作

  • find(x) 找根；union(x,y) 合并两个集合。朴素实现可能退化成链，单次 O(n)。

两个优化

  • 路径压缩：find 时把路径上的节点直接挂到根，后续查询接近 O(1)。
  • 按秩/按大小合并：把矮树挂到高树下（或小集合挂到大集合），树高控制在 O(log n)。
  • 两者一起用，均摊复杂度为 O(α(n))，α 是反阿克曼函数，实际可视为常数。

判断连通分量

  • 初始每个点独立；对每条边 union；最后统计不同根的数量，或维护 components 计数（每成功合并一次减一）。

判断环（无向图）

  • 遍历边 (u,v)：如果 find(u) == find(v)，说明 u、v 已连通，再加这条边就成环；否则 union。
  • 有向图判环不能用并查集，要用拓扑排序/DFS 三色标记。

代码骨架

parent = list(range(n))
rank = [0] * n
def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x
def union(a, b):
    ra, rb = find(a), find(b)
    if ra == rb: return False
    if rank[ra] < rank[rb]: ra, rb = rb, ra
    parent[rb] = ra
    if rank[ra] == rank[rb]: rank[ra] += 1
    return True

应用

  • Kruskal 最小生成树、连通分量、朋友圈/省份数量、账户合并、网格连通性；带权并查集可维护到根的距离/关系。

坑

  • 只写路径压缩不按秩合并仍可能较慢；递归 find 在超深链上可能爆栈；合并前忘了先 find；有向图/带删除的图不适用。
