如何在 GitHub Actions 中缓存依赖（npm / yarn / pip / maven）以显著加速构建？写出关键步骤。

中级编程题DevOps工程师SRE站点可靠性工程师后端开发工程师CI/CD缓存构建加速

题目

编程题：要求写出缓存依赖的 YAML 步骤，并说明缓存命中与失效机制。

参考答案

要点：

  • 用 actions/cache 显式缓存：通过 path（依赖目录）与 key（含操作系统 + 包管理器 + 锁文件哈希）确定缓存键；命中则直接还原，未命中则生成新缓存。
  • 优先用 setup 动作的內建 cache：actions/setup-node 的 cache: npm|yarn|pnpm、actions/setup-python 的 cache: pip 可直接基于锁文件自动缓存 ${GITHUB_REF} 对应目录，代码量更少。
  • 缓存失效策略：key 里一定要包含锁文件内容哈希（如 ${{ hashFiles('**/package-lock.json') }}），锁文件变了 key 就变、自动失效重建；同时配 restore-keys 做前缀回退，最大化复用。

示例（npm）：

- uses: actions/setup-node@v4
  with:
    node-version: 20
    cache: npm          # 自动基于 package-lock.json 缓存
- run: npm ci

或手动：

- uses: actions/cache@v4
  with:
    path: ~/.npm
    key: npm-${{ runner.os }}-${{ hashFiles('**/package-lock.json') }}
    restore-keys: npm-${{ runner.os }}-

说明：缓存不是「越大越好」——只缓存真正省时的依赖目录，避免把构建产物也塞进缓存导致体积膨胀、还原变慢。
