海量日志/订单需要实时接入 Doris，Stream Load、Routine Load、Broker Load 三者该如何选型？

中级场景题大数据开发工程师数据仓库工程师后端开发工程师Doris数据导入ETL

题目

场景题：考察 Doris 多种导入方式的适用边界。

参考答案

要点：

  • Stream Load：通过 HTTP 把本地文件/程序内存里的数据同步推送到 BE，适合小批量、实时导入（单次 MB~GB 级），由客户端发起、返回即知结果。典型用法：业务服务写一条就 curl -XPUT 推一批。
  • Routine Load：基于 Kafka 的持续订阅导入，Doris 自动从 Kafka 拉取、按消费位点持续写入，天然适配「日志/埋点实时入湖」的流场景；断点由 Doris 管理，无需外部调度。
  • Broker Load：通过 Broker（如 HDFS/S3 客户端）异步批量导入远端存储上的大文件（GB~TB 级），适合离线数仓的「T+1 大批量 ETL」；提交任务后异步执行，适合历史数据回填。

选型口诀：实时小批→Stream Load；Kafka 流→Routine Load；离线大文件→Broker Load。还要关注导入频率：高频小批注意合并（compaction）压力，必要时攒批；批量导入设置合理的 max_filter_ratio 容忍脏数据。
