Compose 中副作用(Side Effect)如何处理？LaunchedEffect / DisposableEffect / rememberCoroutineScope 各自适用什么场景，用错会有什么后果？

中级场景题移动端开发工程师Android开发工程师Jetpack Compose副作用LaunchedEffect协程生命周期

题目

说明 Compose 中副作用的语义，以及三个常用 API 的分工与误用后果。

参考答案

要点：

  • 什么是副作用：指重组之外、改变外部世界或有时间维度的操作，如发网络请求、订阅、启动协程、写文件。Composable 应是纯函数，副作用必须交给专用 API，否则重组（可能多次或并发执行）会重复触发，造成请求风暴。
  • LaunchedEffect(key)：进入组合时启动一个协程，key 变化或离开组合时自动取消。适合「某状态变化才执行一次」的效果（如 key 变化触发一次接口拉取）。误用：key 用常量且放在高频重组处，可能只在首次执行一次而错过后续状态。
  • DisposableEffect(key)：进入组合执行并可在 onDispose 里清理，适合注册/反注册（监听、广播）。误用：忘记实现 onDispose 会造成内存泄漏。
  • rememberCoroutineScope()：返回与当前组合绑定的作用域，可在事件回调（如 onClick）里 launch 协程，组合退出自动取消。适合「用户操作触发」的异步，而非进入组合即执行的场景。

小结：副作用要「跟生命周期走」——进入组合启动、离开组合清理；选错 API 轻则重复执行，重则泄漏与崩溃。
