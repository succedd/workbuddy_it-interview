Elasticsearch 的倒排索引原理是什么？写入与近实时搜索（NRT）的流程是怎样的？

中级简答题后端开发工程师搜索算法工程师Elasticsearch倒排索引segmentNRT

题目

考察点：倒排索引、分词、Lucene segment、refresh/flush/translog、近实时语义。

参考答案

要点：

  • 倒排索引：正排是「文档→词」，倒排是「词→文档列表（含词频/位置）」——搜索时先分词查词典定位 posting list，再求交集/并集。这正是搜索引擎快的根源，也是 ES 不擅长频繁更新（倒排重建代价）的原因。
  • 写入流程：文档先写 memory buffer + translog（事务日志防丢）→ 默认每 1 秒 refresh 生成新 segment（此时可搜——所以叫近实时 NRT，不是实时）→ 周期性 flush 把 segment 落盘并清 translog。
  • segment 特性：不可变（immutable）——更新=标记删除+新增版本，删除只是 .del 标记，靠后台 merge 真正物理清除。不可变带来缓存友好与压缩高比，代价是删除/更新是「假的」。
  • 工程推论：refresh_interval 调大（30s）提升写入吞吐但搜索延迟变高；translog durability=request 保证节点崩溃不丢已确认写入。
