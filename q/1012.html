TiDB 兼容 MySQL 的边界在哪里？它的整体架构（TiDB/TiKV/PD）是怎么分工的？

中级简答题数据库开发工程师数据库架构师TiDB分布式数据库RaftHTAP

题目

考察点：计算存储分离、Raft 多副本、PD 调度、MySQL 兼容性边界。

参考答案

要点：

  • 三层架构：TiDB Server（无状态计算层，解析/优化/执行 SQL，可水平扩）→ TiKV（分布式 KV 存储层，数据按 Range 切 Region≈96MB，每 Region 三副本 Raft 组）→ PD（集群大脑：TSO 全局时钟发号、调度 Region 副本与负载均衡）。
  • 水平扩展的本质：数据不是分库分表「切库」，而是切成 Region 自动调度分裂合并——扩容加 TiKV 节点，PD 自动搬 Region，业务无感；这是它相对分库分表中间件的根本优势。
  • 事务：Percolator 模型两阶段提交 + TSO 单调时间戳，快照隔离（ROCKSDB 上的 MVCC），乐观/悲观事务模式可选。
  • 兼容边界：兼容 MySQL 协议与大部分语法，但不支持：外键（v6.6 前后有限支持）、部分存储引擎/字符集、触发器、存储过程；自增 ID 不保证连续（只保证趋势递增，分布式 AUTO_RANDOM 防热点）。迁移前必须做兼容性扫描（ TiUP/_tidb_ 兼容性检查工具）。
