FastAPI 的依赖注入（Depends）是怎么工作的？如何用它优雅地实现统一鉴权和分页？

中级简答题Python后端工程师Python开发工程师后端开发工程师FastAPI依赖注入Depends鉴权分页

题目

考察点：依赖解析树、yield 依赖、可复用依赖。FastAPI 最实用的机制。

参考答案

要点：

  • 机制：Depends(callable) 声明依赖，FastAPI 在路由注册时就分析函数签名，构建出一棵依赖树（包括子依赖），请求到达时按拓扑顺序从叶子到根依次求解，结果缓存到请求作用域（use_cache=True 时同一依赖在一次请求内只执行一次，这点对数据库会话很关键）。
  • 三种依赖形态：普通函数、类实例（Depends(UserService)，自动调用 __init__）、生成器依赖（yield）——yield 之前的代码在请求处理前执行，之后的代码在响应返回后执行，这正是资源清理（关闭 DB 会话、释放锁）的正确位置，且异常时也会走到 finally。
  • 统一鉴权示例：
def get_current_user(token: str = Depends(oauth2_scheme), db=Depends(get_db)) -> User:
    payload = decode(token)   # 失败抛 HTTPException(401)
    user = db.get(User, payload['sub'])
    if not user: raise HTTPException(403)
    return user

@app.get('/me')
def me(user: User = Depends(get_current_user)): ...

把 get_current_user 挂到 APIRouter(dependencies=[Depends(get_current_user)]) 上即可整组路由统一鉴权，无需每个函数重复写。

  • 统一分页：定义 class PageParams: def __init__(self, page: int = 1, size: int = Query(20, le=100))，用 Depends(PageParams) 注入，还可以派生出 Depends(PageParams).depends() 组合出 DTO。
  • 进阶：dependencies=[...] 用于不关心返回值只要副作用的场景（如权限校验）；Security() 是 Depends() 的带 OpenAPI 安全声明版本。
  • 坑：依赖里抛出的 HTTPException 会直接短路整个请求（这是特性不是 bug）；同步依赖函数会在线程池执行，别在里写阻塞的重活。
