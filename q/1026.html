Express 的错误处理中间件为什么必须是四个参数？在 async 路由里抛错为什么捕获不到？

中级简答题Node.js工程师后端开发工程师Express错误处理asyncunhandledRejection中间件

题目

考察点：错误中间件识别机制、异步错误丢失、进程崩溃风险。Express 最经典的坑。

参考答案

要点：

  • 四个参数是「指纹」：Express 靠 fn.length === 4 判断这是错误处理中间件，签名为 (err, req, res, next)。少写一个参数（哪怕不用 next）它就被当成普通中间件，永远收不到错误。
  • 传递路径：同步抛错会被 Express 捕获；但错误中间件必须注册在所有路由之后，且错误发生后沿中间件栈向下寻找最近的错误处理器。
  • async 路由为什么捕获不到：Express 4 只对同步执行做 try/catch。async 函数返回 Promise，reject 后的异常落在微任务队列里，Express 的调用栈早就返回了，框架看不到 → 变成 unhandledRejection，Node 18+ 默认会直接终止进程（线上表现为「服务随机重启」，极难定位）。
  • 四种修法：① 每个 handler 包 try/catch 并 next(err)；② 用 express-async-errors 打补丁，自动给 async 包一层；③ 写高阶包装 const wrap = fn => (req,res,next) => Promise.resolve(fn(req,res,next)).catch(next)；④ 升级 Express 5，官方已支持 Promise rejection 自动转 next(err)。
  • 兜底：进程级必须加 process.on('unhandledRejection') 与 uncaughtException 记日志（uncaughtException 后应优雅退出并交给进程守护重启，不要继续跑）。
  • 加分点：错误中间件里不要忘了判断 res.headersSent，头已发出就只能 next(err) 交给默认处理器；生产环境应返回统一错误体但隐藏堆栈（err.stack 只写日志）。
