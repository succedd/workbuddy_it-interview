Koa 的 ctx 是怎么实现的？delegates 做了什么？为什么它比 Express 的 req/res 更好用？

高级简答题Node.js工程师后端开发工程师Koactxdelegates设计模式

题目

考察点：对象委托、原型代理、API 设计取舍。考察对「框架设计美学」的理解。

参考答案

要点：

  • ctx 的本质：Koa 用 Object.create(context) 创建 context 对象，再把 request 与 response 两个对象挂上去（ctx.request、ctx.response），三者互相持有引用（ctx.request.ctx === ctx）。每个请求一个全新的 ctx，天然隔离，不会有 Express 那种「给 req 加属性可能串到别的请求」的心智负担。
  • delegates 的作用：一个属性委托工具，把 ctx.request/ctx.response 上的属性「搬运」到 ctx 上，支持三种形式：

- getter：读取转发，如 ctx.url → ctx.request.url；

- setter：赋值转发，如 ctx.body = x 实际设置到 ctx.response.body；

- method：方法转发并绑定正确的 this，如 ctx.throw() → ctx.request.throw()。

底层用 Object.defineProperty 在 context 上定义访问器实现，几乎零运行时开销（只是多一层函数调用，V8 能内联）。

  • 为什么更好用：① 扁平 API——ctx.body、ctx.status、ctx.type 一处搞定，不用记 req.query 还是 res.send；② ctx.state 专门给中间件间传值，语义清晰；③ ctx.throw(404) 直接抛 HTTP 错误，与洋葱模型的错误捕获天然契合；④ 因为 ctx 是新建对象，中间件扩展字段（如 ctx.user）不会污染复用对象。
  • 代价：Koa 不做「大而全」，路由、body 解析、静态服务都要自己装（@koa/router、koa-body、koa-static），入门门槛高于 Express，且生态包质量参差，需要团队自己定标准。
  • 加分点：ctx.cookies、ctx.accepts() 是 content negotiation 的实用 API；Koa 2 全面拥抱 async/await，不再需要 co 自动执行器。
