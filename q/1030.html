如何用 Koa 的洋葱模型实现统一的响应包装与全局异常捕获？

中级编程题Node.js工程师后端开发工程师Koa中间件异常处理洋葱模型实践

题目

考察点：中间件工程化、错误语义、与洋葱模型的结合。实操题。

参考答案

要点：

  • 统一下发格式：约定 { code, message, data }。在「最外层」中间件里包住 await next()，读取业务往 ctx.body 里写的结果再统一包装。
  • 全局异常捕获：Koa 的错误会因为 await 链而冒泡到最外层，所以最外层中间件用 try/catch 就能兜住所有下游（包括路由里的异步错误）——这是洋葱模型相比 Express 的最大便利。
app.use(async (ctx, next) => {
  const start = Date.now()
  try {
    await next()
    if (ctx.status === 404 && !ctx.body) ctx.throw(404, '接口不存在')
    // 已返回二进制流（文件下载）时不要包装
    if (!ctx.body || ctx.body instanceof Stream) return
    ctx.body = { code: 0, message: 'ok', data: ctx.body }
  } catch (err) {
    ctx.status = err.status || 500
    ctx.body = { code: err.code || ctx.status, message: err.expose ? err.message : '服务器开小差了', data: null }
    // 5xx 记完整堆栈；4xx 只记摘要，避免日志噪音
    ctx.app.emit('error', err, ctx)
  } finally {
    ctx.set('X-Response-Time', `${Date.now() - start}ms`)
  }
})
  • 几个关键细节：

- err.expose === true 是 Koa 对「可安全暴露给客户端」的错误标记，ctx.throw(400, '参数错误') 自动置位；未标记的（数据库报错等）必须脱敏，绝不能把堆栈吐给前端；

- 不要在包装层强改已 set 的 Content-Type（文件流、SSR 页面会坏）；

- 业务友好错误建议自定义 BizError extends Error 并带 code，避免用 HTTP 500 表达业务失败；

- 顺序：统一响应/异常中间件必须放在最外层（第一个 use），日志与 trace 中间件紧随其后，路由最后。

  • 加分点：配合 ctx.state.traceId 把请求 ID 写进日志与响应头，便于全链路排查。
