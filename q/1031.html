Koa 为什么不内置路由和 body 解析？社区常用组合方案要怎么选、要注意什么？

初级简答题Node.js工程师后端开发工程师Koa中间件koa-routerkoa-body选型

题目

考察点：微内核设计哲学、生态组合、常见安全配置。选型判断题。

参考答案

要点：

  • 为什么内置少：Koa 的设计哲学是微内核 + 中间件组合——核心只负责「请求上下文、洋葱模型、错误冒泡」，其余交给生态。好处是体积小、可替换、无历史包袱；代价是每个项目要自己搭标准，选型能力变成团队成本。
  • 主流组合：

- 路由：@koa/router（原 koa-router，活跃维护的官方组织版）；旧项目里 koa-router 已停更，注意别用错包。

- body 解析：koa-body（支持 multipart 文件上传，功能全）或 @koa/bodyparser（轻量，只处理 JSON/urlencoded）。文件上传才需要 koa-body，纯 JSON API 用轻量的即可。

- 静态资源：koa-static + koa-send，生产环境更推荐交给 Nginx/CDN。

- 安全头：koa-helmet；CORS：@koa/cors；压缩：koa-compress。

- 会话：koa-session（内存/外部 store）——多副本部署必须换 Redis store，否则登录态不共享。

- 日志：koa-logger（开发）/ pino-koa（生产结构化日志）。

  • 必须注意的点：

- 中间件注册顺序决定一切：日志→错误处理→安全头→CORS→body 解析→路由，顺序错了会出现「OPTIONS 预检没被 CORS 中间件处理」「错误没被兜住」；

- koa-body 的 multipart: true 会引入 formidable 与临时文件，要显式设 maxFileSize，否则可被大文件打爆磁盘；

- 不要在生产开 koa-logger（同步写 stdout、性能差）；

- 每个中间件都要能 await next()，忘记 await 会导致洋葱链断裂（响应被提前发出）。

  • 加分点：生态碎片化是 Koa 的主要痛点，团队应在脚手架里固化一套「黄金中间件栈」，避免每个服务各不相同。
