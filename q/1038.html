TypeScript 的条件类型（Conditional Types）和 infer 是怎么用的？如何实现一个类型安全的 get 函数？

高级编程题前端开发工程师前端架构师Web全栈工程师TypeScript类型编程infer条件类型泛型

题目

考察点：类型编程、infer 推断、分布式条件类型。TS 从「会用」到「精通」的分水岭。

参考答案

要点：

  • 语法：T extends U ? X : Y。当 T 是裸类型参数（union）时会发生分布式条件类型（Distributive Conditional Types）——A | B 会被拆开逐个判断再合并：
type ToArray<T> = T extends any ? T[] : never
type R = ToArray<string | number>  // string[] | number[]（不是 (string|number)[]）

避免分布式：用 [T] extends [U] 把两侧包成元组。

  • infer：在 extends 条件里声明一个待推断的类型变量，由编译器反推。经典应用：
type ReturnType<T> = T extends (...a: any[]) => infer R ? R : never
type UnwrapPromise<T> = T extends Promise<infer U> ? U : T
type ElementType<T> = T extends (infer E)[] ? E : never
  • 类型安全的 get 实现：用泛型约束把 key 限定为 K extends keyof T，返回值直接用索引访问类型，编译器自动推导：
function get<T extends object, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key]
}
const u = { id: 1, name: 'a' }
const n = get(u, 'name')   // n: string
// get(u, 'age')           // 编译期报错：'age' 不在 keyof typeof u

如果 key 是运行时变量，就需要 K extends keyof T + 调用处显式标注，或返回 T[K] | undefined 配合类型守卫收窄。

  • 进阶工具：as const 让字面量收窄，从而让 keyof 只包含真实存在的键；satisfies（TS 4.9）做「校验但不拓宽类型」——const cfg = {...} satisfies Config 既校验了结构，又保留了字面量类型，是替代 as 的更安全写法。
  • 实践建议：类型编程要有预算——超过三层的嵌套条件类型会严重损害可读性与编译速度，能用简单泛型+重载解决就别炫技。
