TypeScript 的类型收窄（Narrowing）是怎么工作的？为什么应该优先用 unknown 而不是 any？

中级简答题前端开发工程师前端架构师Web全栈工程师TypeScript类型收窄unknown类型守卫strict

题目

考察点：类型守卫、控制流分析、unknown 的强制校验。实操中最影响代码安全性的点。

参考答案

要点：

  • 类型收窄：TS 通过控制流分析（Control Flow Analysis）在每个代码分支里推断出「更窄」的类型。常见触发方式：

- typeof x === 'string'（原始类型）；

- x instanceof Date（类）；

- 'name' in obj（属性存在性）；

- 判等/真值判断 if (x)、if (x === null)（注意 if (x) 会同时排除 0、''、NaN，是语义陷阱）；

- 自定义类型守卫：function isUser(v: unknown): v is User 或断言函数 asserts v is User。

  • unknown vs any：

- any 关闭所有检查——可以随意取值、调用、赋给任何类型，错误一路传导到运行时报错；

- unknown 只能接收、不能直接使用，必须先收窄才能访问属性/调用方法。它保留的类型安全性正是「来自外部世界的值」需要的：JSON.parse() 的返回值、catch (e)、HTTP 响应、postMessage 数据。

  • 典型模式：
function parse(input: unknown): User {
  if (typeof input !== 'object' || input === null) throw new Error('not object')
  const o = input as Record<string, unknown>
  if (typeof o.name !== 'string') throw new Error('name required')
  return { name: o.name }
}

生产环境更推荐用 zod / io-ts / valibot 做运行时校验并把结果类型推导出来——一次校验同时得到类型和校验，比手写守卫可靠。

  • 工程配置：strict: true 里最容易被忽略的是 useUnknownInCatchVariables（TS 4.4+ 默认随 strict 开启），即 catch (e) 的 e 是 unknown 而不是 any——这正是官方在推动「别把异常当 any 用」。
  • 加分点：as const 与 satisfies 让字面量收窄且不被拓宽；is 守卫在联合类型里能一次性收窄整个对象；never 常用于穷尽性检查（default: const _x: never = action），编译期强制你处理所有分支。
