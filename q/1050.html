Webpack 的 HMR（热更新）原理是什么？为什么有时候改一行代码会整页刷新？

高级故障排查题前端开发工程师前端架构师WebpackHMR热更新模块替换开发体验

题目

考察点：HMR 运行时、模块替换边界、accept 机制。理解后才能调好开发体验。

参考答案

要点：

  • 完整链路：

1. 文件监听：watchpack 监听文件系统变化（注意它靠文件时间戳/轮询，某些编辑器「原子写」或容器挂载会遇到监听不到的情况）；

2. 重新编译：只重新构建受影响的模块（增量编译），产出新的 chunk；

3. 推送：通过 WebSocket（webpack-dev-server 的 HMR 客户端）把 manifest（更新的模块哈希）+ 新 chunk 推给浏览器；

4. 运行时替换：webpack/hot/dev-server 与 module.hot 运行时接收更新，从变化的模块向上寻找「能接受更新的边界」。

  • accept 与冒泡（核心机制）：模块通过 module.hot.accept([依赖], callback) 声明「我能处理这些依赖的更新」。更新到来时，运行时从变更模块开始向父级冒泡：

- 若某模块 accept 了它 → 调用其 callback（通常只是重新执行模块代码，react-refresh 借此实现组件级不丢状态更新）；

- 若某个模块自己不 accept，且没有父级 accept 它 → 冒泡到顶层（entry）→ 没有边界可替换 → 只能 location.reload() 整页刷新。

这就是「改一行就刷新整页」的根因：该模块不在任何 accept 边界内。

  • 为什么常见会整页刷新：

1. React/Vue 组件没配 HMR（老项目手写 ReactDOM.render、未用 react-refresh/vue-loader 的 hot 模式）；

2. 改的是「被 entry 直接使用且非组件」的文件（路由配置、常量、工具函数、store 定义）——它们通常没有 accept 边界；

3. .babelrc/tsconfig/环境变量等构建配置变更 → 需要重建整个模块图，只能刷新；

4. hot: false 或 hotOnly 配置问题、HMR 客户端连不上 WS（端口/代理/HTTPS 混合内容）→ 降级为 live reload。

  • 如何改善：确保框架 loader 开 hot（react-refresh/babel、vue-loader v15+ 自动处理）；用 module.hot.accept 为自定义的顶层模块加边界（如把 router/store 的更新做成 accept 回调里重建）；用 hotOnly 关闭「自动刷新兜底」以便发现未覆盖的边界；webpack-dev-server 的 client.overlay 与日志里会明确写「Hot Module Replacement was not applied, full reload」——先看这条日志再优化。
  • 加分点：HMR 与 React Fast Refresh 的区别——Fast Refresh 是 HMR 之上专为 React 组件实现的能力，能做到保留组件局部 state、区分「只是渲染函数变了」与「Hook 签名变了（则重置状态）」；函数组件之外的文件（常量、工具）变化仍会触发整树刷新。
