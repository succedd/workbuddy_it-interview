腾讯云 CLB 的四层负载均衡和七层负载均衡有什么区别？分别适用于什么场景？

初级简答题公有云售后技术支持系统运维工程师云计算工程师CLB负载均衡四层七层腾讯云

题目

考察点：四层（IP+端口）与七层（应用层内容）转发的本质差异、代理模型的差异（四层 NAT vs 七层双连接）、协议支持与选型。这是 CLB 追问链的起点题。

参考答案

转发依据不同：

  • 四层负载均衡：基于「IP + 端口」转发。CLB 发布 VIP（三层 IP 地址）加四层端口号来识别流量，对需要处理的流量做 NAT 转发到后端服务器，并记录这条 TCP/UDP 连接——后续这条连接的所有流量都转发到同一台后端；
  • 七层负载均衡：在四层基础上再解析应用层内容（HTTP 头部、URL、浏览器类别、语言等）决定转发，也称为「内容交换」——例如同一个 Web 服务的请求，可以根据 URL 路径把 /api 和 /static 转发到不同的后端分组。

代理模型不同：七层要先与客户端建立连接（三次握手）、收到真正的应用层报文后才能选择后端，因此七层设备更像代理服务器——CLB 与客户端、与后端服务器分别建立 TCP 连接。

选型要点：

  • 四层（TCP/UDP）：适用于关注高并发性能、不需要解析应用层内容的场景，如游戏、数据库中间件、IoT 接入；
  • 七层（HTTP/HTTPS）：适用于 Web 应用，需要按域名/URL 路由、HTTPS 卸载、重定向、会话保持（Cookie）等能力；
  • 云上实践：腾讯云 CLB 的七层基于自研 STGW（Nginx 内核），四层基于自研统一接入网关 TGW（DPDK 高性能转发，单集群可支持亿级并发），两者均为集群部署、无单点。
