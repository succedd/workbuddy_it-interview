【单选】一个单例 Bean 同时实现了 InitializingBean 接口、标注了 @PostConstruct 的 init1() 方法，并在 @Bean 上指定了 initMethod="init2()"。初始化阶段的执行顺序是： A. afterPropertiesSet() → @PostConstruct init1() → init2() B. @PostConstruct init1() → afterPropertiesSet() → init2() C. init2() → afterPropertiesSet() → @PostConstruct init1() D. 三者顺序不确定，取决于 Bean 注册顺序

中级单选题Java后端工程师Java开发工程师后端架构师SpringBean生命周期@PostConstructInitializingBean单选

题目

考察点：Bean 初始化回调的三种机制及官方固定执行顺序、Aware 回调的位置、为什么官方推荐 @PostConstruct。追问链第二环：Bean 生命周期的精确时序。

参考答案

正确答案：B。

官方定义的初始化顺序（Spring Framework 文档明确列出）：

  1. @PostConstruct 标注的方法（JSR-250 注解，现代 Spring 应用的最佳实践，不与 Spring 接口耦合）；
  2. InitializingBean 的 afterPropertiesSet()（官方不推荐——会让业务代码耦合 Spring 接口）；
  3. 自定义 init-method / @Bean(initMethod=...)（既想要解耦又不使用注解时的方案）。

销毁侧顺序同理：@PreDestroy → destroy() → 自定义 destroy-method。

时序全景（答题加分项）：实例化（构造器）→ 属性填充（依赖注入）→ Aware 回调（如 BeanNameAware.setBeanName、ApplicationContextAware.setApplicationContext，发生在普通属性填充之后、初始化回调之前）→ BeanPostProcessor 前置处理 → 初始化回调（按 B 的顺序）→ BeanPostProcessor 后置处理（AOP 代理就是在这里生成的）→ Bean 就绪。

补充要点：初始化回调在容器的单例创建锁内执行，官方提醒 @PostConstruct 里只做配置校验和轻量数据准备——重量级异步初始化（如预热数据库）应放到 SmartInitializingSingleton.afterSingletonsInstantiated() 或监听 ContextRefreshedEvent，避免初始化死锁；若多种机制配置了同一个方法名，该方法只会被执行一次。
