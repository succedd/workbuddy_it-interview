如何用 Redis 实现去重、基数统计与布隆过滤器式判重？

中级场景题Java后端工程师后端开发工程师RedisSetBitmapHyperLogLog去重布隆过滤器

题目

日活 UV 统计、爬虫 URL 去重、抽奖不重复等场景，如何选择合适的 Redis 数据类型（Set / Bitmap / HyperLogLog / 布隆过滤器）？

参考答案

精确去重：用 Set 的 SADD + SCARD/SISMEMBER，适合中小规模、需判断「是否在集合内」的场景（如抽奖已中奖名单）。

位图判重：Bitmap（基于 String 的位运算）用 SETBIT/GETBIT，按用户 ID 位标记，省内存，适合「海量布尔标记」如签到、是否访问过。

基数统计：UV 只需「大约多少人」而非具体名单时，用 HyperLogLog 的 PFADD/PFCOUNT，12 KB 内存估数亿级基数，误差约 0.81%，代价是不存明细。

布隆过滤器式判重：Redis 本身无原生 BF 命令（部分模块/RedisBloom 提供），核心是用多位哈希降低误判；爬虫 URL 去重可用 Set（精确）或 HLL/Bitmap（近似）。选型：要精确明细用 Set，只要计数用 HLL，只要标记用 Bitmap。
