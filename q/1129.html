为什么 CSS 会阻塞渲染、JavaScript 会阻塞 HTML 解析？defer、async、preload、关键 CSS 内联分别如何缓解渲染阻塞？

中级简答题前端开发工程师后端开发工程师技术经理渲染阻塞deferasyncpreload关键CSS

题目

请解释浏览器在解析 HTML 时遇到 <link> 样式表与 <script> 脚本的阻塞行为，以及 defer / async / preload / 关键 CSS 内联 各自如何打破阻塞、适用什么场景。

参考答案

CSS 阻塞渲染：浏览器构建渲染树需要 DOM + CSSOM，所以 <link> 样式表会阻塞首次渲染（但不会阻塞 HTML 解析）；样式未就绪前不会 paint，否则会闪。

JS 阻塞解析：默认 <script> 会阻塞 HTML 解析并等待下载执行完（因为脚本可能改 DOM），这就是“脚本放在底部”的原因。

defer：下载不阻塞解析，延迟到 DOM 解析完成、DOMContentLoaded 前按顺序执行，适合依赖 DOM 的外部脚本。

async：下载不阻塞解析，下载完立即执行、不保证顺序，适合独立无依赖的脚本（如统计 SDK）。

preload：用 <link rel=preload> 提前以高优先级拉取关键资源（字体/JS/CSS），但不执行，配合 as 属性让资源更早到位。

关键 CSS 内联：把首屏必需的少量 CSS 直接内联进 <head>，其余非关键 CSS 异步加载，消除首屏渲染前的那一次 Render-Blocking 请求。
