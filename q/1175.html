开放讨论：Vue3 的编译时优化（静态提升 / PatchFlag / Block Tree）是如何把虚拟 DOM 的 diff 从「全量比对」降到「靶向比对」的？结合编译产物说明。

高级开放讨论题前端开发工程师Vue3编译优化PatchFlag虚拟DOMdiff

题目

考察点：渲染机制与 diff 优化原理（本链 diff 环节）。要求讲清编译器在编译期能做哪些静态分析，以及运行时如何只比对动态节点，而非整棵 vnode 树。

参考答案

要点：

  • 静态提升（hoistStatic）：编译器在编译期识别出「永远不变的静态节点/属性」，把它们提升到 render 函数外面只创建一次，后续更新直接复用同一 vnode，不再参与 diff，减少比对数量。
  • PatchFlag（动态标记）：对模板里真正会变的节点，编译器在编译期就给它打上「动态类型编码」，例如 TEXT（只有文本变）、CLASS、PROPS（并附上具体属性名数组）。运行时 diff 不再递归比所有属性，而是只按 PatchFlag 去更新对应那一项（如只比 class、只比指定的 props），把 O(全属性) 降成 O(标记项)。
  • Block Tree（动态区块）：编译器把模板按 v-if/v-for/插槽等「结构可能变化」处切成 Block，每个 Block 内收集一个 dynamicChildren 动态子节点数组。diff 时只遍历 dynamicChildren 这个扁平数组，而不是整棵子树，跳过了所有静态子树；v-for 列表的 key 比对也只在动态节点间进行。
  • 一句话总结：Vue2 的 diff 是「递归比整棵树」，Vue3 靠「编译期标记 + 运行时只走动态节点」把比对成本从树规模降到「动态节点数」，这是 Vue3 渲染性能大幅领先的关键之一。
