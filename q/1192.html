Spring Boot 的自动配置（Auto-configuration）核心机制是什么？AutoConfigurationImportSelector 是如何找到并加载候选配置类的？

初级简答题Java后端工程师Spring Boot自动配置AutoConfigurationImportSelector条件注解

题目

考察点：自动配置加载全流程，以及 spring.factories 与 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports 的版本差异。要求讲清『扫描清单 → 条件过滤 → 注册 Bean』三步。

参考答案

要点：

  • 入口：@EnableAutoConfiguration 通过 @Import 引入 AutoConfigurationImportSelector（它实现 DeferredImportSelector，延迟到普通配置类处理完再执行）。其 selectImports() 读取候选配置类清单。
  • 清单来源（版本差异）：Spring Boot 2.7 之前扫描各 jar 的 META-INF/spring.factories 中 EnableAutoConfiguration 键；2.7 起废弃 spring.factories，改为扫描 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports（每行一个全限定类名）。spring-boot-autoconfigure 自带一份数百个内置配置类清单。
  • 条件过滤（按需加载）：清单里的类都是 @Configuration，几乎都带 @Conditional 注解。核心三件套：@ConditionalOnClass（classpath 有指定类才生效，如引入 spring-web 才加载 WebMvc 自动配置）、@ConditionalOnMissingBean（容器中已有同类型 Bean 就跳过，保证用户自定义优先）、@ConditionalOnProperty（配置项匹配才生效，如配了 spring.datasource.url 才加载数据源）。
  • 结果：只有满足条件的配置类才被注册为 BeanDefinition，进而创建默认 Bean；用户可用自己的 @Bean 覆盖，或用 spring.autoconfigure.exclude 排除。

核心：自动配置 = 『按依赖列清单 + 按条件筛清单 + 用户 Bean 优先』，所以『引入 starter 即自动生效、可被自定义覆盖』。
