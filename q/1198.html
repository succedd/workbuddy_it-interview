缓存穿透有哪些常见解决方案？请对比缓存空值、布隆过滤器、接口参数校验三种手段的适用场景与取舍。

中级简答题Java后端工程师后端开发工程师Redis缓存穿透布隆过滤器空值缓存

题目

考察点：穿透的三大防御手段，以及各自适用边界（空值缓存的 TTL 陷阱、布隆过滤器的误判、参数校验的位置）。要求能说明『为什么常组合使用』。

参考答案

要点：

  • 缓存空值 / 默认值：查 DB 返回空时，也在 Redis 里存一个空标记（如 NULL）并设置较短 TTL（如 5 分钟）。后续相同请求直接命中空值返回，不再打 DB。取舍：实现简单，但会占用一些缓存空间，且 TTL 内若数据真被创建会返回旧空值（故 TTL 要短），攻击者若用海量不同不存在的 key 仍会撑大缓存。
  • 布隆过滤器（Bloom Filter）：在写入 DB 时把 key 标记进布隆过滤器；请求到来、缓存 miss 后先查布隆过滤器，『不存在』就直接拦截，根本不查 DB。取舍：空间效率极高、查询快；缺点是存在哈希冲突带来的误判（说存在不一定真存在，但说不存在一定不存在），且需定期重建以反映下架数据。
  • 接口参数校验（入口限制）：在 API 入口校验请求参数合法性（id>0、格式、范围），非法请求直接返回错误，从源头挡掉大部分恶意流量。取舍：成本最低、必须做，但只能挡『格式非法』，挡不住『格式合法但不存在』的key，需与前两者配合。

核心：生产上通常三层组合——参数校验挡明显非法、布隆过滤器挡不存在的 key、空值缓存兜底漏网之鱼，形成递进防御。
