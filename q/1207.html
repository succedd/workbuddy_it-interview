故障排查题：你新配了一条 Prometheus 告警规则，但该告警时它不触发（或反过来一直 firing 误报）。请列出常见排查方向与原因。

中级故障排查题DevOps工程师公有云售后技术支持Prometheus告警规则故障排查Alertmanager

题目

考察点：告警排障的二分定位法——先确认『规则是否 FIRING』，再区分是 expr/for/数据问题还是 Alertmanager 通知链路问题。要求给出可操作的排查顺序。

参考答案

要点：

  • 第一步：看 Prometheus UI 的 Alerts 页，确认该规则当前状态。若已是 FIRING 但没收到通知 → 问题在 Alertmanager 通知链路；若根本没 FIRING → 问题在表达式/数据。
  • 没 FIRING 的常见原因：① expr 写错、阈值方向反了（> 写成 <），在 Graph 里手动跑 expr 验证；② for 时长太长或目标只闪一下就恢复，先用 for: 0 验证是否真命中；③ label 拼写/大小写不匹配导致查询为空，用 label_values 确认 label 存在；④ 目标 down、scrape 失败（Targets 页非 UP），没有数据自然算不出。
  • FIRING 但没通知的常见原因：① Alertmanager 的 route/receiver 配错，告警没路由到正确接收人；② 被 silences 静默规则压制；③ group_wait/group_interval 还没到发送窗口，看起来像『没发』。
  • 窗口/分辨率：rate()[1m] 窗口太小或 scrape 间隔过大，可能取不到足够样本导致结果异常。

核心：先确认 FIRING 状态二分定位——没 FIRING 是 expr/for/数据问题，FIRING 没通知是 Alertmanager 路由/静默问题，不要一上来就改配置。
