配置题：请手写一条 Prometheus 告警规则——例如『某实例 CPU 使用率持续 5 分钟超过 80%』或『HTTP 5xx 率超过 5%』，并说明 expr / for / labels / annotations 各字段含义。

高级配置题DevOps工程师公有云售后技术支持Prometheus告警规则AlertmanagerSLO

题目

考察点：告警规则落地——能写出合法的 YAML 规则，并讲清四个字段的语义（尤其 for 防抖、labels 做路由、annotations 给上下文）。要求阈值贴合 SLO。

参考答案

要点：

  • 示例（CPU 使用率超阈值）：
groups:
  - name: instance-health
    rules:
      - alert: HighCpuUsage
        expr: 100 * (1 - avg by(instance)(rate(node_cpu_seconds_total{mode="idle"}[5m]))) > 80
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "实例 {{ $labels.instance }} CPU 使用率过高"
          description: "CPU 使用率已持续 5 分钟超过 80%（当前 {{ $value | printf \"%.1f\" }}%）"
  • expr：触发条件的 PromQL 表达式；CPU 使用率 = 1 - 空闲率，必须用 rate() 算 Counter。
  • for：条件需持续满足的时长（5m），避免瞬时抖动误报；设为 0 则一命中立即告警。
  • labels：附加到告警的标签，常用于路由（如 severity=warning/page 决定走哪个 receiver）和分组。
  • annotations：人类可读摘要/描述，支持模板变量 {{ $labels.xxx }} 与 {{ $value }}（命中时表达式的值），便于运维一眼定位。
  • HTTP 5xx 率示例：expr: sum(rate(http_requests_total{code=~"5.."}[5m])) by(service) / sum(rate(http_requests_total[5m])) by(service) > 0.05。

核心：一条规则 = 正确的 expr + 合理的 for 防抖 + labels 做路由 + annotations 给上下文；阈值要贴合 SLO，而非拍脑袋。
