系统设计题：Grafana 如何从 Prometheus 取数并搭建监控看板？一条典型的生产看板应包含哪些核心面板（结合 RED / USE 方法）？告警与看板如何配合？

高级系统设计题DevOps工程师公有云售后技术支持PrometheusGrafanaRED方法USE方法监控看板

题目

考察点：监控可视化与告警的分工——Grafana 作为 Prometheus 的可视化层，如何用 RED（服务）/USE（资源）方法组织面板，以及看板（事后定位）与告警（事中通知）的互补关系。

参考答案

要点：

  • 取数链路：Grafana 添加 Prometheus 为 Data Source（填其 URL），看板 Panel 用 PromQL 查询从 Prometheus 拉时序并渲染。Grafana 只负责可视化与（可选）告警通知，存储与计算都在 Prometheus；也可在 Grafana 侧直接基于 Panel 查询配 alerting。
  • RED 方法（请求类服务）：Rate（每秒请求数 QPS）、Errors（错误率）、Duration（请求耗时分布/分位数）。对应面板：QPS 曲线、5xx 错误率、P50/P95/P99 延迟。
  • USE 方法（资源类）：Utilization（利用率，如 CPU/内存/磁盘）、Saturation（饱和度，如队列长度/等待）、Errors（错误数）。对应面板：资源利用率、磁盘 IO 等待、网络错包。
  • 典型看板结构：① 总览/SLO 健康度 ② 流量（QPS）③ 错误（5xx/异常率）④ 延迟（分位数）⑤ 饱和度（资源利用率）⑥ 依赖（下游/DB/缓存）⑦ 实例维度下钻。
  • 告警与看板配合：看板用于事后定位与趋势观察，告警用于事中即时通知。看板上的关键曲线（错误率、P99）应同时配 Prometheus/Grafana 告警；告警触发后运维从对应看板下钻定位。告警阈值参考看板长期基线与 SLO。

核心：Grafana = Prometheus 的可视化层；用 RED（服务）/USE（资源）组织面板覆盖『率/错/延迟/饱和度』，看板负责下钻、告警负责即时通知，二者互为补充。
