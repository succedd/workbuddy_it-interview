React 18 的 Fiber 架构与并发渲染（Concurrent Rendering）解决了什么问题？可中断渲染、优先级调度是如何实现的？

高级开放讨论题前端开发工程师前端架构师ReactFiber并发渲染优先级调度Suspense

题目

追问链第 4 问：从虚拟 DOM 的协调进一步到 Fiber——React 的渲染引擎重构。

参考答案

要点：

  • 解决的核心问题：旧版 Stack Reconciler 是同步递归遍历虚拟 DOM，一旦开始就无法打断，组件树很大时主线程被长时间占用，导致输入卡顿、动画掉帧。Fiber 把渲染拆成可中断、可恢复的小任务单元，让 React 在浏览器空闲时分段工作，并在高优先级任务（如用户输入）到来时暂停低优先级渲染。
  • Fiber 是什么：React 16 引入的新协调引擎，把组件树重构为一串「Fiber 节点」链表。每个 Fiber 记录组件类型、状态、副作用与指向父子/兄弟的指针，使遍历可增量进行、随时挂起与恢复。
  • 并发特性（React 18）：通过 startTransition、useDeferredValue、useTransition 标记「非紧急更新」，React 用优先级调度区分紧急（点击、输入）与可延后（大列表筛选）更新；Suspense 配合并发特性实现「等待数据时展示兜底而不阻塞整页」。
  • 代价与权衡：并发带来更强响应性，但要求组件写成「可中断安全」——避免在渲染中做副作用、保证纯渲染；useTransition 包裹的更新可能被丢弃重算，需理解其语义。
