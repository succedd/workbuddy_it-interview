用 Sentinel 给一个「下单接口」配置 QPS 限流 + 慢调用比例熔断 + 热点参数限流，并说明规则如何持久化到 Nacos，避免应用重启后丢失。

高级场景题Java后端工程师Sentinel流控规则熔断规则热点参数限流Nacos持久化

题目

考察点：Sentinel 在真实项目中的落地实战——流控/熔断/热点规则配置，以及规则持久化（动态数据源）这一高频踩坑点，高级场景题。

参考答案

要点：

  • QPS 流控：给 /order/create 配 FlowRule，grade=FLOW_GRADE_QPS、count=200、controlBehavior=流速均摊(冷启动/排队)；超阈值直接 Blocked（走 BlockException 兜底返回「繁忙」）。
  • 慢调用比例熔断：配 DegradeRule，grade=SLOW_REQUEST_RATIO，slowRtMs=500、count(比例)=0.5、timeWindow=10s、minRequestAmount=5；当慢调用比例超 50% 且请求数达标即跳闸 10s，期间快速失败，半开探测恢复。
  • 热点参数限流：用 ParamFlowRule 对「userId」维度限流，例如普通用户单机 QPS=5，对 VIP 用户设 paramItem 例外项放行更高；防止单个用户刷单拖垮接口。
  • 规则持久化（关键）：默认规则存内存，重启即丢。需接入 DynamicRuleDataSource：实现 ReadableDataSource 从 Nacos/Apollo/ZK 拉取 JSON 规则并注册到 FlowRuleManager.register2Property；同时用 WritableDataSource 在控制台改规则后写回 Nacos，做到「控制台改→Nacos→各实例拉取」双向同步。
  • 监控：接 Sentinel Dashboard 看实时 QPS/熔断事件，规则来源统一走 Nacos 配置中心。
