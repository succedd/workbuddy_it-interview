首屏加载慢，如何沿「关键渲染路径 CRP」定位瓶颈并优化？请列出至少 5 个可落手的手段及其作用。

中级场景题前端开发工程师关键渲染路径首屏优化代码分割CDN缓存

题目

考察点：关键渲染路径（HTML→CSSOM→Render Tree→布局→绘制）的理解，以及资源体积、请求数、缓存等工程优化手段的体系化运用。

参考答案

要点：

  • 定位：用 DevTools Network/Performance 看 TTFB、资源 waterfall、长任务；区分瓶颈在「网络下载」还是「主线程解析/执行」。
  • 压缩与精简：开启 Gzip/Brotli；Tree-shaking 删死代码；删 console/注释；图片转 WebP/AVIF 并压缩。
  • 代码分割与懒加载：路由级 import() 按需加载，首屏只下发必要 JS/CSS，避免单包过大。
  • 减少阻塞：CSS 放头部并异步/内联关键 CSS；JS 用 defer/async 避免阻塞解析；preload 关键资源。
  • 传输优化：上 HTTP/2（多路复用、头部压缩）+ 域名分片收敛；静态资源走 CDN 就近返回。
  • 缓存：HTML 短时缓存、带哈希的静态资源设长缓存（Cache-Control max-age + immutable），配合 Service Worker 离线缓存。
  • 协议/连接：开启 TLS1.3、HTTP/2 Server Push（谨慎）、DNS 预解析（dns-prefetch）、连接预建（preconnect）。
