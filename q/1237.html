页面滚动或交互时掉帧卡顿，如何判断是「重排/重绘」还是「主线程长任务（JS 执行）」导致的？分别给出优化手段。

中级场景题前端开发工程师重排重绘合成层长任务渲染优化

题目

考察点：浏览器渲染机制（重排/重绘/合成）与 JS 长任务的区分，以及减少主线程阻塞的实操手段，典型渲染优化场景题。

参考答案

要点：

  • 判定方法：Performance 面板看「Rendering」里 Layout/Recalculate Style 是否耗时高（重排重绘），或看 Main 线程是否有长任务（>50ms 的 JS 执行）。肉眼抖动 + Layout 紫条 = 重排；长任务黄块 = JS 阻塞。
  • 重排（Reflow）/重绘（Repaint）优化：避免逐帧读写 offsetTop 等触发强制同步布局（读写分离、批量改样式）；用 transform/opacity 走合成层（只合成不重排重绘）；动画用 will-change 提层；减少 DOM 数量与嵌套。
  • 长任务优化：用 requestAnimationFrame 把视觉更新对齐到帧；用 setTimeout/任务分片或 scheduler 拆分长任务；防抖节流高频事件；Web Worker 把计算移出主线程；IntersectionObserver 替代滚动监听。
  • 关键认知：transform/opacity 走 GPU 合成层几乎不触发重排重绘，是动画性能的核心手段；其余属性改动多半引发重排，代价最高。
