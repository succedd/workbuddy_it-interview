请手写一个基于 IntersectionObserver 的图片懒加载（进入视口才加载真实 src），并说明响应式图片、字体与预加载的配套优化手段。

高级编程题前端开发工程师懒加载IntersectionObserver响应式图片font-display资源优化

题目

考察点：资源加载优化的落地实现与生态手段（懒加载/响应式图片/font-display/preload），检验工程细节，高级编程题。

参考答案

要点（讲解）：

懒加载核心是「先用占位、进入视口再换真实地址」，IntersectionObserver 比监听 scroll 更省性能（由浏览器异步触发、不阻塞主线程）。配套优化：① 响应式图片用 srcset + sizes 或 <picture> 按 DPR/视口下发合适分辨率；② 字体用 font-display: swap 避免 FOIT 阻塞文字；③ 首屏关键资源 preload、非关键 prefetch；④ 图片用 WebP/AVIF + CDN。

<img class="lazy" data-src="/real.jpg" src="data:image/svg+xml,%3Csvg%20xmlns='http://www.w3.org/2000/svg'/%3E" alt="">
const io = new IntersectionObserver((entries) => {
  for (const e of entries) {
    if (e.isIntersecting) {                 // 进入视口
      const img = e.target;
      img.src = img.dataset.src;             // 换真实地址
      img.onload = () => img.classList.remove('lazy');
      io.unobserve(img);                     // 加载后停止观察
    }
  }
}, { rootMargin: '200px' });                // 提前 200px 预加载

document.querySelectorAll('img.lazy').forEach(el => io.observe(el));

注意：现代浏览器原生支持 loading="lazy"，无兼容要求可直接用；IntersectionObserver 用于需要更细控制（如淡入、占位骨架）的场景。
