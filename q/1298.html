做响应式布局时，px / em / rem / vw / vh / % 该怎么选？媒体查询和 clamp() 分别适合什么场景？

初级简答题前端开发工程师页面重构工程师UI/UX设计师CSS响应式媒体查询clamp单位

题目

考察点：相对单位的基准差异，以及媒体查询与流体排版的取舍。

参考答案

相对单位的基准不同：

  • px：绝对像素，不随用户设置缩放，适合边框、1px 细线等；
  • em：相对自身或父元素字号，嵌套会层层累积，容易失控；
  • rem：相对根元素（html）字号，最可控，适合全局字号与间距；
  • vw / vh：相对视口宽高（1vw = 视口宽度的 1%），适合随屏幕缩放的尺寸；注意移动端 vh 受地址栏影响，可用 dvh/svh/lvh；
  • %：相对包含块的对应属性；宽度百分比基于父宽，而 padding-top 的百分比也基于父宽，这是经典坑。

媒体查询（@media）适合按设备特征/视口做结构性切换：

@media (min-width:30em) and (orientation:landscape){...}
  • 由可选的媒体类型（screen/print/all）+ 媒体特性（width、hover、color、orientation 等）组成，用 and / not / or / 逗号列表组合；只有「区间」类特性可加 min- / max- 前缀；
  • 注意：即使查询为 false，挂在 <link media> 上的样式表仍会下载，只是不应用——不要指望靠它省流量；
  • Level 4 支持更简洁的 @media (30em <= width <= 50em)、not(hover) 等区间与布尔语法。

clamp() 做「流体排版」：clamp(MIN, VAL, MAX) 等价于 max(MIN, min(VAL, MAX))：

h1{font-size:clamp(1.8rem,2.5vw,2.8rem)}

字号随视口连续变化，但不小于 1.8rem、不超过 2.8rem，一行替代多段媒体查询；同类还有 min()、max()。

实践建议：字号/间距用 rem，需要连续缩放用 vw + clamp()；断点式的结构变化（侧栏折叠、栅格列数切换）用媒体查询；务必配好 <meta name=viewport>，否则移动端不会按设备宽度渲染。
