题目

考察点：XSS 与 CSRF 的成因差异及分层防御意识。

参考答案

一、XSS（跨站脚本）

定义：攻击者向页面注入恶意客户端代码，由受害者浏览器执行，从而绕过访问控制、冒充用户。MDN 指出其成因是「不可信数据进入应用」或「动态内容未经验证就输出给用户」。分三类：

  • 存储型：恶意脚本被永久存到服务器（评论、昵称等），其他用户加载页面即中招，危害最大；
  • 反射型：诱导点击带 payload 的链接或提交特制表单，服务器把脚本回显在响应里（错误页、搜索结果）；
  • DOM 型：不经过服务端，是前端代码把不可信数据写入 DOM 环境（innerHTML、eval、location 等）所致。

XSS 防御（按层划分）：

  1. 输出编码/转义：按上下文（HTML、属性、URL、JS）分别转义；前端禁止用 innerHTML 拼接用户输入，优先 textContent；
  2. 输入校验与白名单：富文本用成熟 sanitizer（如 DOMPurify）过滤标签与属性；
  3. CSP（内容安全策略）：用 Content-Security-Policy 限制脚本来源、禁内联脚本，配合 nonce、子资源 integrity；MDN 在会话劫持一节也推荐用严格 CSP 限制数据泄露途径；
  4. Cookie 加 HttpOnly：让脚本读不到会话 Cookie，降低 XSS 的收益。

二、CSRF（跨站请求伪造）

定义：攻击者诱导受害者浏览器在已登录、且不知情的情况下向后端发请求，例如 <img src='https://bank.example.com/withdraw?account=bob&amount=1000000'>，或用隐藏表单 + 脚本自动提交。

攻击前提（缺一不可）：浏览器自动携带目标站点 Cookie，且服务端仅凭 Cookie 判断身份、无额外校验。

防御组合（MDN 给出）：

  1. GET 保持幂等：改变数据的操作一律用 POST 等非 GET 方法，POST 端点不接受查询串参数；
  2. CSRF Token：服务端下发与会话绑定、攻击者无法预测的随机令牌，随表单/请求头提交并比对，登录时重新生成；
  3. SameSite：会话 Cookie 设 SameSite=Strict/Lax，跨站请求不携带，服务端视其为未认证；
  4. Token + SameSite 一起部署，以覆盖子域等 SameSite 帮不上忙的场景。

一句话区别：XSS 是「脚本被注入并在你的源里执行」，靠输出编码 + CSP + HttpOnly；CSRF 是「浏览器替你带了 Cookie 发请求」，靠 Token + SameSite + 幂等方法。两者常被组合：攻击者可用 XSS 载荷发起 CSRF。
