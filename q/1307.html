场景题：有 1000 个接口要请求，但浏览器同域并发连接有限、服务端也扛不住。如何用 Promise 实现「限制并发数为 N」的批量请求？

中级场景题前端开发工程师Web全栈工程师全栈开发工程师JavaScriptPromise并发控制手写代码

题目

考察点：Promise 并发语义 + 手写并发调度器，并理解 JS 单线程下的「并发」含义。

参考答案

为什么不能直接 Promise.all：MDN 提供 all / allSettled / any / race 四个并发方法，但它们没有上限——Promise.all(urls.map(fetch)) 会瞬间打出上千个请求；浏览器对同域 HTTP/1.1 的并发连接数有限（通常 6），服务端也有限流。另外 MDN 提醒：JS 本质是单线程，同一时刻只有一个任务在执行，「并发」只是控制权在不同 Promise 之间切换，真正的并行要靠 worker 线程。

核心思路（任务池 + 递归补位）：维护一个大小为 N 的「在跑队列」，每完成一个就从待办里取下一个补上，直到全部跑完。

function limitConcurrency(tasks, limit = 5) {
  return new Promise((resolve) => {
    const results = new Array(tasks.length);
    let next = 0, running = 0, done = 0;
    const run = () => {
      if (done === tasks.length) return resolve(results);
      while (running < limit && next < tasks.length) {
        const i = next++;
        running++;
        Promise.resolve()
          .then(() => tasks[i]())           // 关键：同步任务也走微任务，避免递归爆栈
          .then(v => { results[i] = { status: 'fulfilled', value: v }; })
          .catch(e => { results[i] = { status: 'rejected', reason: e }; })
          .finally(() => { running--; done++; run(); });
      }
    };
    run();
  });
}

// 用法：任务写成「函数」，而不是已经开始的 Promise
const tasks = urls.map(u => () => fetch(u).then(r => r.json()));
const results = await limitConcurrency(tasks, 5);

三个要点：

  1. 任务必须是惰性函数，若直接传已经调用的 Promise，请求在入队前就全发出去了；
  2. 用 Promise.resolve().then(...) 把「取下一个」推迟到微任务，避免同步递归过深导致栈溢出；
  3. 用 .catch 兜住每个任务，即可获得 allSettled 语义（一个失败不影响其它）；反之若想「失败即中止」，则在 catch 里统计拒绝数并整体 reject。

加分：如需限制 QPS，可在任务包装里加延时队列；如需超时/重试，用 AbortController 与重试计数；生产环境可直接用维护良好的 p-limit。同时要能说清「为什么不直接用 Promise.all」。
