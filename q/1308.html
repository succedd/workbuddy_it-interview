浅拷贝和深拷贝的本质区别是什么？JSON.parse(JSON.stringify()) 有哪些致命缺陷，structuredClone 又如何？

中级简答题前端开发工程师HTML/CSS/JS工程师JavaScript深浅拷贝structuredClone结构化克隆

题目

考察点：拷贝层级的本质、JSON 序列化的类型损失，以及结构化克隆算法的边界。

参考答案

本质区别：拷贝第几层。

  • 浅拷贝只复制第一层，嵌套对象仍是同一引用（Object.assign({}, obj)、扩展运算符 {...obj}、Array.prototype.slice/concat）。改内层会互相影响。
  • 深拷贝递归复制所有层，得到完全独立的对象。

JSON.parse(JSON.stringify(obj)) 的缺陷：

  1. 丢类型：Date 变字符串，RegExp / Map / Set / Error 全变 {}；
  2. 丢值：undefined、函数、Symbol 作为对象属性会被删除，数组中的会变成 null；
  3. 报错或失真：BigInt 直接抛 TypeError，NaN / Infinity 变 null；
  4. 循环引用直接抛错（Converting circular structure to JSON）；
  5. 不保留原型链，类实例退化为普通对象。

手写深拷贝（面试常考）：用 WeakMap 记录已拷贝对象以解决循环引用（弱引用也避免「记录表」自身造成泄漏），对 Date / RegExp / Map / Set 分类处理，并用 Object.create(Object.getPrototypeOf(obj)) 保留原型。

structuredClone（现代首选，2022 年起主流浏览器广泛可用）：基于结构化克隆算法完成深拷贝，且支持循环引用：

const original = { name: 'MDN' };
original.itself = original;
const clone = structuredClone(original);
// clone !== original，clone.name === 'MDN'，且 clone.itself === clone
  • 支持 Date / RegExp / Map / Set / ArrayBuffer / TypedArray / Blob / File 等，能正确处理循环引用；
  • 支持转移可转移对象，转移后原对象失效：
structuredClone(uInt8Array, { transfer: [uInt8Array.buffer] });
// 之后 uInt8Array.byteLength === 0
  • 限制：不能克隆函数、DOM 节点、Symbol 与类原型方法，遇到不可序列化的部分会抛 DataCloneError；也不像手写方案那样能保留自定义原型。

选型：只改第一层 → 用浅拷贝，避免无谓开销；现代浏览器且数据可能含 Date / 循环引用 → 优先 structuredClone；需要保留原型与类实例、或处理不可克隆类型 → 手写递归或 lodash.cloneDeep；老环境且数据是纯 JSON → 才考虑序列化方案，并清楚它会丢什么。
