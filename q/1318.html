题目

JIT 即时编译是如何工作的？分层编译有哪几个层级？逃逸分析能带来哪些优化？

参考答案

Java 代码最初由解释器逐条解释执行字节码，启动快但速度有限。当某些代码被反复执行成为「热点」后，JVM 会把它提交给即时编译器编译成本地机器码，编译后的代码存放在独立的 Code Cache 中，之后直接执行机器码，这就是 JIT 的基本思想——边解释边编译，兼顾启动速度与峰值性能。

热点探测：HotSpot 基于计数器的探测，包括方法调用计数器和回边计数器（回边对应循环体），两者之和超过阈值就触发 JIT 编译。阈值可通过 -XX:CompileThreshold 调整；在分层编译模式下阈值判定还结合采样频率。编译在后台线程完成，编译期间照常解释执行，避免等待。

分层编译（默认开启，-XX:+TieredCompilation）把编译分成五个层级：L0 是纯解释执行；L1 是 C1 编译且不带 profiling；L2 是 C1 编译带少量计数 profiling；L3 是 C1 编译带完整 profiling，用于收集分支、类型等统计信息；L4 是 C2 编译，基于 L3 收集的信息做深度优化。最常见路径是解释器 → L3 → L4：先用 C1 快速出代码，再在热点足够热时交给 C2 深度优化；L1、L2 则在 C2 忙碌或方法只热一阵等场景中充当过渡层。C1 追求编译速度，C2 追求代码质量，两者配合实现「快启动 + 高峰值」。

方法内联是 JIT 最重要的优化之一：把小方法体直接复制到调用点，消除调用开销，同时让被内联的代码暴露在更大的优化视野里，其余优化才有的放矢。这也是为什么高频路径上的 getter、简单工厂方法性能几乎无损。

逃逸分析是 C2 的基础分析：判断对象的作用域是否逃出方法或线程。若对象不逃逸，HotSpot 可做三类优化：

  1. 标量替换（主要方式）：把对象拆散为若干基本类型标量，直接分配在寄存器或栈帧上，绕过堆分配；
  2. 锁消除：只被单线程访问的局部对象（如方法内 new 的 StringBuffer），其上的同步操作直接删除；
  3. 栈上分配：概念上存在，但 HotSpot 实际通过标量替换实现，不能简单表述为「对象直接在栈上分配」。

注意：逃逸分析依赖全局数据流分析，成本高且结果不稳定，「HotSpot 真的把对象放到栈上」是常见误区，回答时表述要严谨。
