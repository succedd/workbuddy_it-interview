Redis 的 mem_fragmentation_ratio 多大算健康？内存碎片是怎么产生的，activedefrag 主动碎片整理又是如何工作的？

中级简答题后端开发工程师DBA数据库管理员系统运维工程师Redis内存碎片activedefragjemalloc运维

题目

考察点：对 Redis 内存碎片成因、监控指标健康区间与 4.0+ 主动碎片整理机制的掌握。

参考答案

什么是内存碎片

碎片就是「分配了但没法再利用」的空闲内存。例如申请 32 字节只用 24 字节，多出的 8 字节放不下别的数据，就成了碎片。碎片不影响性能，但增加内存消耗。

碎片怎么来的

  • 分配器的固定大小类：Redis 默认用 jemalloc，按 8、16、32、64 字节等一系列固定档位分配。要 17 字节就给 32 字节，最多浪费近一半。
  • 频繁修改与删除：数据更新扩容会重新分配更大的块，旧块留下空隙；删除后 Redis 通常不把内存归还操作系统，页级出现无法利用的空洞。

怎么监控

用 INFO memory 查看：mem_fragmentation_ratio = used_memory_rss / used_memory，即物理内存除以分配器申请内存。

| 区间 | 含义 |

| --- | --- |

| 约 1.0 ~ 1.5 | 健康区间，正常 |

| 大于 1.5 | 碎片偏高，存 2G 数据可能占 3G+，需整理 |

| 小于 1 | 部分内存被换出到 Swap，比碎片更危险 |

注意 rss 与 used_memory 之差还含进程开销、共享库等，不能直接当碎片大小。

activedefrag 主动整理

Redis 4.0 起内置主动整理（依赖 jemalloc）：开启 config set activedefrag yes 后，Redis 会把分散的数据拷贝到新位置、释放出连续的空闲空间归还操作系统，在不阻塞服务的前提下让内存重新紧凑。触发与限流由四个参数控制：active-defrag-ignore-bytes 500mb（碎片量达 500MB 才启动）、active-defrag-threshold-lower 50（碎片率超 1.5 才启动）、active-defrag-cycle-min 20 与 active-defrag-cycle-max 50（占用 CPU 时间比例上下限，避免影响主线程）。另外，安全重启节点（如集群中先切主从）也能彻底重整内存。
