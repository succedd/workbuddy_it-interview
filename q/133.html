题目

请列举索引优化、查询优化、表结构优化策略。

参考答案

MySQL SQL优化常用方法

一、索引优化

1. 合理创建索引

-- 为常用查询字段创建索引
CREATE INDEX idx_name ON users(name);

-- 创建联合索引（遵循最左前缀原则）
CREATE INDEX idx_name_age ON users(name, age, city);

2. 索引使用原则

| 原则 | 说明 |

|------|------|

| 最左前缀 | 联合索引必须从最左列开始匹配 |

| 覆盖索引 | 查询字段全在索引中，避免回表 |

| 索引下推 | 减少回表次数（MySQL 5.6+）|

| 区分度高 | 选择性高的列适合建索引 |

3. 避免索引失效

-- ❌ 索引失效场景
SELECT * FROM users WHERE LEFT(name, 3) = 'Tom';   -- 函数操作
SELECT * FROM users WHERE age + 1 = 18;             -- 运算操作
SELECT * FROM users WHERE name != 'Tom';            -- != 操作
SELECT * FROM users WHERE name LIKE '%Tom%';        -- 前缀%
SELECT * FROM users WHERE name = 123;               -- 类型隐式转换

-- ✅ 正确写法
SELECT * FROM users WHERE name LIKE 'Tom%';         -- 后缀%可用索引
SELECT * FROM users WHERE age = 17;                 -- 避免运算

---

二、SQL语句优化

1. SELECT 优化

-- ❌ 避免 SELECT *
SELECT * FROM users;

-- ✅ 指定字段（减少数据传输，可使用覆盖索引）
SELECT id, name, age FROM users;

2. WHERE 条件优化

-- ❌ 对索引列使用函数
SELECT * FROM orders WHERE YEAR(create_time) = 2024;

-- ✅ 改为范围查询
SELECT * FROM orders 
WHERE create_time BETWEEN '2024-01-01' AND '2024-12-31';

3. JOIN 优化

-- 小表驱动大表（IN / EXISTS 选择）
-- 当子查询结果集小，用 IN
SELECT * FROM A WHERE id IN (SELECT id FROM B);  -- B小

-- 当主查询结果集小，用 EXISTS
SELECT * FROM A WHERE EXISTS (SELECT 1 FROM B WHERE B.id = A.id);  -- A小

-- JOIN 时关联字段必须有索引
SELECT a.*, b.name 
FROM orders a 
LEFT JOIN users b ON a.user_id = b.id;  -- user_id 和 id 要有索引

4. 分页优化

-- ❌ 深度分页性能差（offset越大越慢）
SELECT * FROM orders LIMIT 1000000, 10;

-- ✅ 方案1：子查询/覆盖索引
SELECT * FROM orders 
WHERE id >= (SELECT id FROM orders LIMIT 1000000, 1) 
LIMIT 10;

-- ✅ 方案2：记录上次最大ID（推荐）
SELECT * FROM orders WHERE id > 最后一条id LIMIT 10;

5. GROUP BY / ORDER BY 优化

-- ORDER BY 字段要与索引顺序一致，且排序方向一致
-- 避免 filesort（Using filesort）

-- ❌ 混合排序方向导致无法用索引
SELECT * FROM users ORDER BY age ASC, create_time DESC;

-- GROUP BY 默认会排序，不需要排序时加 ORDER BY NULL
SELECT age, COUNT(*) FROM users GROUP BY age ORDER BY NULL;

---

三、表结构优化

1. 字段类型选择

-- ✅ 使用合适的数据类型
-- 整型优先：TINYINT < SMALLINT < INT < BIGINT
-- 固定长度用 CHAR，变长用 VARCHAR
-- 时间用 DATETIME 或 TIMESTAMP，不用字符串
-- 避免 NULL（NULL会影响索引统计）

ALTER TABLE users MODIFY COLUMN status TINYINT NOT NULL DEFAULT 0;

2. 范式与反范式

-- 适当冗余字段，减少 JOIN（反范式）
-- 比如订单表冗余用户名，避免频繁关联用户表
ALTER TABLE orders ADD COLUMN user_name VARCHAR(50);

---

四、查询分析工具

1. EXPLAIN 执行计划

EXPLAIN SELECT * FROM users WHERE age = 18;

| 关键字段 | 说明 |

|---------|------|

| type | ALL(全表) < index < range < ref < eq_ref < const（越右越好）|

| key | 实际使用的索引 |

| rows | 预估扫描行数（越少越好）|

| Extra | Using index=覆盖索引✅，Using filesort❌，Using temporary❌ |

2. 慢查询日志

-- 开启慢查询
SET GLOBAL slow_query_log = ON;
SET GLOBAL long_query_time = 1;  -- 超过1秒记录

-- 查看慢查询配置
SHOW VARIABLES LIKE '%slow_query%';

---

五、其他优化手段

1. 分库分表

  • 垂直分表：大字段单独拆出去（如大文本、图片URL）
  • 水平分表：按范围/Hash分片（如按用户ID取模）

2. 读写分离

  • 主库写，从库读
  • 利用 MyCat、ShardingSphere 等中间件

3. 缓存策略

热点数据 → Redis缓存 → 减少DB查询

4. 批量操作

-- ❌ 循环单条插入
INSERT INTO users VALUES (1, 'Tom');
INSERT INTO users VALUES (2, 'Jerry');

-- ✅ 批量插入
INSERT INTO users VALUES (1,'Tom'),(2,'Jerry'),(3,'Lucy');
