请讲讲 InnoDB 的 MVCC 实现原理，以及 RC 与 RR 在 ReadView 生成时机上的区别。

高级简答题后端开发工程师Java后端工程师MVCCReadViewundo log

题目

考察多版本并发控制的底层三要素及快照可见性算法。

参考答案

MVCC（多版本并发控制） 让读写互不阻塞，核心依赖三要素：隐藏字段、undo log 版本链、ReadView。

1. 隐藏字段

每行数据有 InnoDB 自动添加的隐藏列：DB_TRX_ID（最后一次修改该行的事务 ID）、DB_ROLL_PTR（回滚指针，指向 undo log 中的旧版本）、DB_ROW_ID（无主键时的行 ID）。

2. undo log 版本链

每次更新该行，旧版本写入 undo log，通过 DB_ROLL_PTR 串成一条版本链（链首最新、链尾最旧）。

3. ReadView（可见性判断）

ReadView 记录当前活跃（未提交）事务 ID 列表 m_ids、m_up_limit_id（最小活跃 ID）、m_low_limit_id（下一个将分配的事务 ID）等。读取时按规则判断某版本是否对当前事务可见，不可见就顺着版本链找上一个版本。

RC 与 RR 的关键区别

  • RC（读已提交）：每次 SELECT 前都重新生成一个 ReadView，因此能读到别的事务最新已提交的数据，产生「不可重复读」。
  • RR（可重复读）：只在事务第一次 SELECT 时生成一个 ReadView，之后一直复用，所以同一事务内多次读结果一致。

补充：MVCC 解决快照读的不可重复读/幻读，而当前读（加锁读）靠 Next-key Lock 防幻读。
