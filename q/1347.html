MySQL 慢查询如何排查与优化？EXPLAIN 执行计划里哪些字段最关键？

中级简答题后端开发工程师Java后端工程师DBA数据库管理员慢查询EXPLAINSQL优化

题目

考察线上慢 SQL 定位手段与执行计划解读能力。

参考答案

排查步骤：

  1. 开启慢查询日志（slow_query_log=ON，long_query_time 设阈值），用 mysqldumpslow 或 pt-query-digest 找出慢 SQL。
  2. 对目标 SQL 加 EXPLAIN 查看执行计划。
  3. 结合 SHOW PROFILE / performance_schema 看各阶段耗时。

EXPLAIN 关键字段

  • type（访问类型）：从好到坏 system > const > eq_ref > ref > range > index > ALL。出现 ALL（全表扫描）或 index（全索引扫描）需警惕。
  • key / possible_keys：实际使用的索引与候选索引，若为 NULL 说明没走索引。
  • rows：预估扫描行数，越大越慢。
  • Extra：Using filesort（额外排序）、Using temporary（用临时表）、Using where、Using index（覆盖索引，好现象）都值得关注。

常见优化手段

  • 建立/调整索引，构造覆盖索引，避免索引失效（如函数操作、隐式类型转换、前导模糊 LIKE '%x'）。
  • 深分页优化：LIMIT 100000,10 改为「游标分页 / 延迟关联」——先按主键取 ID 再 JOIN。
  • 减少 SELECT *、拆分大事务、避免 OR 改 UNION。

示例（延迟关联）：

SELECT * FROM t JOIN (SELECT id FROM t WHERE ... LIMIT 100000,10) x USING(id);
