为什么说 Java 中只有值传递，没有引用传递？

初级简答题Java后端工程师后端开发工程师值传递引用传递方法参数

题目

考察对 Java 方法参数求值策略的理解，以及如何解释对象参数“看起来像引用传递”的现象。

参考答案

结论：Java 只有值传递（pass-by-value）。无论是基本类型还是对象引用，方法接收的都是调用方值的副本。

原理分析

  • 基本类型：形参是实参值的拷贝，方法内修改形参不影响原变量。
  • 引用类型：传递的是“引用（对象地址）的值的拷贝”，即形参和实参指向同一个对象。

为什么对象看起来像引用传递？

  • 通过形参修改对象内部字段（如 obj.setName(...)）会影响原对象，因为二者指向同一堆内对象。
  • 但若在方法内让形参重新指向新对象（obj = new Object()），原引用不会变，这正说明传的是引用值的副本，而非引用本身。

对比

| 传递方式 | 传递内容 | 能否改变调用方变量本身 |

| :--- | :--- | :--- |

| 值传递（Java 实际行为） | 值的副本 | 不能 |

| 引用传递（如 C++ &） | 变量别名 | 能 |

面试要点：区分“改变对象状态”和“改变引用绑定”，前者不证明引用传递。
