如何判断对象是否可被回收？分代收集与 G1 收集器的工作原理是什么？

中级简答题Java后端工程师后端开发工程师GC可达性分析GC Roots分代收集G1

题目

考察可达性分析、GC Roots、分代收集算法及 G1 的特点。

参考答案

结论：Java 用可达性分析（以 GC Roots 为根）判定对象生死，采用分代收集；G1 以 Region 化布局和“可预测停顿”成为现代服务端主流收集器。

对象可回收判定

  • 不使用引用计数（无法解决循环引用）。
  • GC Roots 包括：虚拟机栈局部变量引用、本地方法栈 JNI 引用、方法区静态属性引用、方法区常量引用。从这些根出发不可达的对象才可被回收。

分代收集算法

  • 新生代（对象朝生夕死）：用复制算法（Eden:Survivor = 8:1:1，利用率高）。
  • 老年代：用标记-整理或标记-清除（整理无碎片但慢，清除快但有碎片）。

G1（Garbage-First）

  • 将堆划分为多个大小相等的 Region，新生代/老年代不再物理隔离。
  • 用 Remembered Set 记录跨 Region 引用，避免全堆扫描。
  • 步骤：初始标记 → 并发标记 → 最终标记 → 筛选回收（按回收价值排序，在用户设定停顿目标内回收）。
  • 优点：空间整合无碎片 + 可预测停顿（可指定 MaxGCPauseMillis）。

对比

| 收集器 | 算法 | 特点 |

| :--- | :--- | :--- |

| Serial/Parallel | 分代 | 吞吐优先，STW 长 |

| CMS | 标记-清除 | 并发低延迟，有碎片 |

| G1 | 标记-整理+复制 | 可预测停顿，平衡吞吐与延迟 |
