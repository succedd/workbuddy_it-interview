Spring 事务的七种传播行为是什么？@Transactional 常见的失效场景有哪些？

中级简答题Java后端工程师后端开发工程师Spring事务@Transactional传播行为事务失效回滚

题目

考察 Spring 声明式事务的传播行为语义，以及 @Transactional 不生效/不回滚的典型坑。

参考答案

结论：@Transactional 基于 AOP（JDK 动态代理 / CGLIB）实现；传播行为解决“方法互相调用时事务如何边界”的问题；自调用、异常被吞、非 public 方法等都会导致失效。

七种传播行为（重点记 3 个）

  • REQUIRED（默认）：有事务则加入，无则新建；内外同属一个事务，任一回滚整体回滚。
  • REQUIRES_NEW：总是新建事务，挂起外层；内外相互独立。
  • NESTED：有事务则开嵌套（父子），父回滚子必回滚，子可独立回滚。
  • 其余：SUPPORTS（有则加入否则非事务）、MANDATORY（必须有事务否则抛异常）、NOT_SUPPORTED（非事务并挂起）、NEVER（非事务，有事务抛异常）。

常见失效场景

  1. 自调用：同类方法 A 调 @Transactional 方法 B，代理未拦截，事务失效（可用 AopContext.currentProxy() 获取代理调用）。
  2. 异常被 catch 吃掉：未重新抛出，拦截器感知不到，不回滚。
  3. 非 public 方法：早期 Spring 仅代理 public 方法（Spring 6 类代理放宽但仍受限制）。
  4. 数据库引擎不支持：如 MySQL myisam 根本不支持事务。
  5. 未配置 rollbackFor：默认只对 RuntimeException/Error 回滚，Checked 异常需显式 rollbackFor。
  6. Bean 未被 Spring 管理或方法 final/static 导致无法代理。

对比

| 失效原因 | 本质 |

| :--- | :--- |

| 自调用 | AOP 代理未生效 |

| 吞异常 | 拦截器无感知 |

| myisam | 底层不支持事务 |
