组相联（Set-Associative）Cache 的地址如何划分？与直接映射、全相联在定量上有何关系？

高级简答题后端开发工程师硬件工程师Cache组相联全相联

题目

考察组相联地址字段与三种映射方式的定量关系。

参考答案

结论

组相联是「直接映射」与「全相联」的折中：先把 Cache 分成若干组（set），组内再放多行（路 way）。地址切成 Tag + SetIndex + Offset。

定量关系

  • 路数（way）：每组行数。1 路 = 直接映射；全相联 = 只有 1 组（SetIndex=0）。
  • 组数 = Cache 总行数 / 路数。
  • SetIndex 位数 = log₂(组数)；Tag 位数 = 地址位 − SetIndex 位 − Offset 位。

算例（Cache 共 64 行，4 路组相联，块 16B）

  • 组数 = 64 / 4 = 16 组 → SetIndex = log₂16 = 4 位。
  • Offset = log₂16 = 4 位。
  • Tag = 32 − 4 − 4 = 24 位。

三种映射对比

| 方式 | 冲突率 | 比较器/查找 | 硬件成本 |

|---|---|---|---|

| 直接映射（1 路） | 高（易抖动） | 比 1 个 Tag | 最低 |

| 组相联（k 路） | 中 | 组内比 k 个 Tag | 中 |

| 全相联（1 组） | 低 | 比全部 Tag | 最高、最慢 |

路数↑ → 冲突失效↓，但 Tag 位↑、每组需 k 个比较器并行、命中延迟略增；实际 CPU 常用 8~16 路 L1。
