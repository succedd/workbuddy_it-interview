Java 中 == 和 equals() 的区别是什么？为什么在重写 equals() 时通常必须同时重写 hashCode()？如果不重写会有什么后果？

初级简答题Java后端工程师JavaequalshashCode哈希集合约定

题目

考察点：equals/hashCode 契约与哈希集合正确性，是 Java 基础中区分「背过」和「真懂」的核心简答题。

参考答案

要点（== 与 equals 区别）：

  • == 比较地址（基本类型比值）；equals 是方法，默认比地址，业务类通常重写为比较「业务字段」是否相等。
  • 比较内容应优先用 equals，且字符串比较务必用 equals 而非 ==。

要点（为什么要重写 hashCode）：

  • Java 规范约定：若 a.equals(b) 为 true，则 a.hashCode() == b.hashCode() 必须成立（反之不要求）；即「相等对象必须有相等哈希码」。
  • HashMap / HashSet / Hashtable 等哈希集合先用 hashCode 定位桶，再用 equals 判断是否同一元素。

要点（不重写的后果）：

  • 只重写 equals 不重写 hashCode，两个 equals 相等的对象可能算出不同哈希码，被放进不同桶——在 HashSet 中出现「重复元素」，在 HashMap 中「get 不到刚 put 的对象」，破坏集合语义。
  • 因此标准做法是：用相同字段计算 equals 与 hashCode（IDE/Record/Lombok 可自动生成），保证二者一致。
  • 补充：hashCode 相等的对象不一定 equals 相等（哈希冲突允许），所以桶内仍需 equals 二次确认。
