一个方法在生产环境抛出 NullPointerException（NPE），但代码里没有明显写 `.getXxx()` 的空指针调用。请描述你的排查思路，并说明哪些「隐藏」场景会触发 NPE。

中级故障排查题Java后端工程师JavaNPE空指针自动拆箱Optional

题目

考察点：NPE 的真实成因（尤其是自动拆箱）与排查手段，典型线上故障排查题，检验是否踩过自动拆箱的坑。

参考答案

要点（排查思路）：

  • ① 看异常堆栈（stack trace）顶部的业务类名与行号，这是最直接的定位点；
  • ② 在可疑行加日志/断点，确认哪个引用为 null；
  • ③ 借助 APM/日志平台按 traceId 还原调用链，看上游传参是否漏判空；
  • ④ 用 Optional 或防御性判空（Objects.requireNonNull）在入口处提前失败、给出明确报错而非裸 NPE。

要点（隐藏的 NPE 触发场景）：

  • 自动拆箱：Integer a = null; int b = a; 会自动调用 a.intValue() 抛 NPE——这是最隐蔽的来源（包装类型转基本类型时）；
  • 集合取元素：map.get(key) 返回 null 后直接参与运算；
  • 链式调用：user.getAddress().getCity() 中间任一环为 null 即崩，建议用 Optional 链式或判空；
  • 方法返回 null 被直接使用：调用第三方/老接口未判空；
  • equals 写反：str.equals(x) 当 str 为 null 抛 NPE，应写成 "常量".equals(str) 或 Objects.equals。
  • 根因归类：绝大多数 NPE 是「本不该返回 null 的地方返回了 null」或「拆箱未保护」，优先用 Optional/默认值/契约约束消除，而非到处 try-catch。
