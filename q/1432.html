请手写一个正确重写 equals() 与 hashCode() 的 User 类（基于 id 与 name 两个字段判断相等），并说明 equals 必须满足哪些约定。

高级编程题Java后端工程师JavaequalshashCode重写契约

题目

考察点：equals/hashCode 的正确实现与五大约定，是一道检验代码功底的高级编程题，要求代码与讲解并重。

参考答案

要点（讲解）：

正确重写需满足 equals 的五大约定：① 自反性（x.equals(x) 为 true）；② 对称性（x.equals(y) 同 y.equals(x)）；③ 传递性；④ 一致性（对象未修改时多次调用结果一致）；⑤ 对任何非 null 的 x，x.equals(null) 返回 false。同时必须保证 equals 相等的对象 hashCode 相等。下面用 Objects 工具类实现，自动处理 null 与一致性。

import java.util.Objects;

public class User {
    private final long id;
    private final String name;

    public User(long id, String name) { this.id = id; this.name = name; }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;                              // 自反/性能
        if (o == null || getClass() != o.getClass()) return false; // 类型与 null 判断
        User user = (User) o;
        return id == user.id && Objects.equals(name, user.name);  // 字段比较
    }

    @Override
    public int hashCode() {
        return Objects.hash(id, name);   // 与 equals 使用相同字段
    }
}

要点（易错点）：

  • 用 getClass() != o.getClass() 而非 instanceof 可避免子类破坏对称性（若允许子类，则需改用 instanceof + 组合校验）；
  • 比较字段时基本类型用 ==、引用类型用 Objects.equals 以安全处理 null；
  • hashCode 与 equals 必须用「同一组字段」计算，否则破坏哈希集合语义（见前题）。
  • 现代替代：Java 16+ 可直接用 record User(long id, String name) 自动生成符合约定的 equals/hashCode。
