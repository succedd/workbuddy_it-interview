题目

考察 Terraform 状态管理：state 的作用、漂移检测、remote state 与 state locking，是 IaC 面试的核心题。

参考答案

state 里存了什么

terraform.tfstate 是 Terraform 的「真实世界资源 ↔ 配置代码」映射表：每条 resource 的实例 ID、属性快照、依赖关系、敏感字段（base64，明文敏感！）。plan 的本质 = 配置文件 diff state diff 真实云上资源。

为什么不能手改手删

  • 手改 state 后，Terraform 认为的「真实」与云上实际脱节 → 下次 plan/apply 会做出错误的增删改（比如把还在用的数据库删掉重建）；
  • 误删 state 条目不会删云资源，但会造成「孤儿资源」——代码里删了它却永远不 apply 成功；
  • 正确姿势：terraform state list / show / rm（显式管理）、terraform import 收编存量资源、terraform refresh（或 plan 的 -refresh-only）同步漂移。

多人协作的 state 冲突

  1. Remote State：state 放 S3 / OSS / Terraform Cloud 等远端，而不是各自笔记本上的本地文件；
  2. State Locking：S3 + DynamoDB（或 OSS 锁表）实现 apply 互斥——有人 apply 时其他人被阻塞，防止并发写 state 互相覆盖；
  3. 环境隔离：dev/staging/prod 用不同的 state 文件（workspace 或目录/后端前缀隔离），爆炸半径分离；
  4. CI/CD 统一执行：apply 只在流水线里做，本地只跑 plan 出 diff。

面试加分点

  • state 里的敏感信息（数据库密码等）不会被加密，后端必须开静态加密 + 严格访问控制；
  • -target 只应救急不该常规化（会造成 state 与实际目标偏差）；
  • 漂移（drift）的根因是「绕过 Terraform 手工改控制台」，治理靠权限收口 + 定期 -refresh-only 告警。
