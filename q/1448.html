OpenGL 里 VBO / VAO / EBO 各存什么？为什么移动端 DrawCall 次数比三角形数量更影响性能？

中级简答题游戏客户端工程师游戏引擎工程师Unity游戏开发工程师AR/VR开发工程师OpenGLVBOVAODrawCall合批

题目

考察顶点数据组织（VBO/VAO/EBO）与 DrawCall 开销的本质：CPU 侧状态切换与驱动的提交成本。

参考答案

三个缓冲对象各存什么

  • VBO（Vertex Buffer Object）：显存里的顶点原始数据（位置/法线/UV 交错打包的二进制块）；
  • VAO（Vertex Array Object）：「如何解读 VBO」的状态集合——每个属性的 stride/偏移/数据类型/是否归一化，配合 glVertexAttribPointer 一次记录，之后绘制只需绑定 VAO；
  • EBO（Element Buffer Object）：顶点索引，让共享顶点只存一份（一个矩形 4 顶点 6 索引），省显存与顶点着色器调用量。

三者关系：VAO 是「索引卡」，指向一个或多个 VBO 的解读方式，EBO 挂在 VAO 上。

DrawCall 为什么比三角形数更致命

一次 glDrawElements = 一次 CPU → GPU 的命令提交：

  1. CPU 侧要做状态校验与切换（绑定纹理/Shader/Uniform 检查），这部分在驱动里是串行开销；
  2. 命令要经过驱动翻译进 GPU 命令队列，CPU 与 GPU 之间有同步与提交成本；
  3. 移动端是瓦片渲染架构（TBDR），DrawCall 还牵涉 Tiles 数据的反复处理。

所以「1000 个 DrawCall 各画 10 三角形」远慢于「10 个 DrawCall 各画 1000 三角形」——GPU 画三角形很快，喂命令的 CPU 才是瓶颈。

合批优化

  • 静态合批：静态物体变换后烘焙进一个大 VBO；
  • 动态合批：小网格每帧 CPU 重算（顶点少时划算）；
  • GPU Instancing：同一网格+材质画 N 份，一个 DrawCall + 每实例偏移数据（草、树、子弹首选）；
  • 除此之外：图集合并纹理、减少材质/Shader 变体切换、Unity 里查 Rendering Statistics 的「Saved by batching」。
追问：DrawCall 与 SetPass Call 的区别？——SetPass（换材质/Pass）比普通 DrawCall 更贵，因为它强制 GPU 清空并重设渲染状态。
