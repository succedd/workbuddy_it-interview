Linux 内核的设备树（Device Tree）是干什么的？没有它之前是什么局面？驱动和设备如何通过 compatible 匹配？

中级简答题嵌入式软件工程师固件工程师系统软件工程师设备树DTScompatible嵌入式Linux

题目

考察设备树机制：描述与代码分离、DTS/DTB 编译链、compatible 匹配规则，是嵌入式 Linux 面试核心题。

参考答案

解决什么问题

ARM 生态早年每个板子都在内核源码里硬编码一个 arch/arm/mach-xxx/board-xxx.c，把内存布局、GPIO、I2C 挂了什么器件全部写死在 C 里——换个板子改一次内核，产生海量重复的板级代码。设备树把「硬件有什么」从内核 C 代码里抽出来，变成一份数据描述文件：内核代码只保留「怎么驱动」，启动时读入描述即可适配不同硬件。

编译与传递链

.dts（板级源文件，可 include .dtsi 公共部分）
  → dtc 编译 → .dtb（二进制 blob）
  → bootloader（U-Boot）把它放进内存，把地址告诉内核
  → 内核启动时解析，生成 platform_device 等设备

同一个内核镜像 + 不同 dtb = 支持不同板卡。

节点与 compatible 匹配

i2c@1 {
    status = "okay";
    temp@48 {
        compatible = "myvendor,tsensor-v2", "myvendor,tsensor-v1";
        reg = <0x48>;
    };
};
  • 驱动侧的 of_match_table 列出它能伺候的 compatible 字符串；内核逐节点扫描，字符串对上就 probe 这个驱动；
  • compatible 可以列多个（如上从新到旧），内核按精确匹配优先：先找 v2 的专用驱动，找不到退化到 v1 通用驱动——这是硬件兼容演进的常用手法；
  • status = "okay"/"disabled" 控制节点是否启用；pinctrl、reg、interrupts、clocks 等属性把资源交给内核统一分配。

面试加分点

  • x86 用 ACPI 做同类事情，设备树主要用于嵌入式（ARM/RISC-V）；
  • dtb 是运行时可覆盖的：bootloader 可以用 U-Boot 的 fdt 命令改属性（改 MAC 地址、关闭某器件）不改文件；
  • 设备树语法错（如 reg 长度与 #address-cells 不符）是 bring-up 阶段「设备 probe 不上」的常见根因，用 ls /proc/device-tree、dmesg | grep probe 排查。
