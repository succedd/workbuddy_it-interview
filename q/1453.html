FFmpeg 转码的内部流程是怎样的？CRF、preset、码率三者如何影响质量与体积？压制视频该怎么选参数？

中级简答题音视频开发工程师流媒体架构师WebRTC工程师FFmpegCRFpreset转码

题目

考察 FFmpeg 转码管线（解封装→解码→滤镜→编码→封装）与核心参数的量化取舍，是音视频岗高频实操题。

参考答案

转码管线

输入文件 → 解封装(demux) → 解码(decode) → 滤镜链(filter: 缩放/水印/字幕)
        → 编码(encode) → 封装(mux) → 输出文件

对应命令要素：ffmpeg -i in.mp4 -vf scale=1280:-2 -c:v libx264 -crf 23 -preset medium -c:a aac -b:a 128k out.mp4。-c copy（转封装）跳过中间三步所以秒级完成，但改不了编码格式。

三个核心参数

  1. CRF（恒定质量，x264/x265）：0–51，越小质量越高。x264 默认 23（肉眼无损约 18）。CRF 是「质量恒定、码率随内容浮动」——动作片码率高、静态画面码率低，同一 CRF 不同片源体积不可比；
  2. preset：ultrafast→placebo 十档，控制编码器搜索的穷举程度。越慢 = 同质量体积越小，但编码耗时指数上升。点播压制用 slow 附近，实时转码只能 veryfast；
  3. 码率（-b:v）：与 CRF 二选一。直播/带宽受限场景用「码率封顶」模式（-maxrate -bufsize），体积可预估但质量随内容波动。

选型口诀：点播存档 → CRF + slow；带宽受限/直播 → 码率封顶 + 快 preset；要控制总体积 → 两遍编码（2-pass）逼近目标码率。

画质相关的其他关键点

  • 分辨率与码率要匹配：1080p 给 500kbps 必然糊，压不动先降分辨率（720p）而不是硬降码率；
  • x265 同画质比 x264 省约 30–40% 体积，但编码慢 3–5 倍、部分老设备解码不支持；
  • -g（GOP）与关键帧间隔影响 seek 精度与 HLS 切片：直播 GOP 通常 2×帧率；
  • 音频 -b:a 128k AAC 对大多数场景足够，音乐内容 192k+。
追问：为什么有的视频「拖动进度条卡」？——关键帧间隔太大，seek 只能跳到最近关键帧再快进解码。
