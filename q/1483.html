为什么 v-for 列表一定要绑定 key？用 index 做 key 有什么问题？

初级简答题前端开发工程师Vue2虚拟DOMkey

题目

从虚拟 DOM Diff 角度说明 key 的作用，以及 index 作 key 导致的典型 Bug。

参考答案

key 是 Diff 算法判断节点是否可复用的身份标识。同层级对比时，Vue 优先按 key 匹配旧节点：key 相同则原地复用并打补丁，不同则当新节点创建。

用 index 作 key 的问题：列表头部/中间插入或删除时，后续所有节点的 index 都变了，Vue 会把「内容错位的旧节点」当成「同一个节点」就地更新——① 多做无谓的 DOM 更新；② 带有内部状态的组件（输入框勾选、滚动位置、动画）状态会串位；③ 过渡动画也无法正确追踪。

正确做法：用数据的唯一业务 id 作 key，且同列表内 key 稳定唯一。
