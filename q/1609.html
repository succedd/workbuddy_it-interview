PostgreSQL 的 MVCC 多版本并发控制是如何实现的？它与 MySQL InnoDB 的 MVCC 有何本质区别？

初级简答题后端开发工程师数据库工程师PostgreSQLMVCC事务

题目

考察 PG 核心并发机制与事务可见性。

参考答案

要点：

  • 实现：PG 每行有隐藏字段 xmin（插入该版本的事务 ID）、xmax（删除 / 更新该版本的事务 ID）。每个事务开始时拿一个快照（snapshot）记录当前活跃事务区间；判断某行版本是否对当前事务可见，依据 xmin/xmax 与快照的可见性规则——已提交且在快照之前、且未被后续事务删除的版本才可见。更新即写新版本 + 标记旧版本 xmax，旧版本成为「死元组（dead tuple）」。
  • 与 InnoDB 区别：InnoDB 用 undo log + 事务 ID + 回滚指针在聚簇索引上构造历史版本，读取时按需回溯；PG 则是行上直接保留多版本，历史版本就在表 / 堆里。
  • 代价不同：PG 的死元组需要 VACUUM / AUTOVACUUM 回收，否则表膨胀、性能下降；InnoDB 的 undo 由 purge 线程清理。PG 的 REPEATABLE READ 通过快照实现，且对写-写冲突用Serializable 快照隔离（SSI）可检测序列化异常。
