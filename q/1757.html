Rails 里出现 N+1 查询（一次列表触发几十条 SQL），你如何定位并解决？

中级场景题后端开发工程师RubyRailsN+1ORM性能

题目

考察点：ORM 经典性能坑——N+1，以及 Rails 预加载（eager loading）的正确用法。

参考答案

要点：

  • 定位：打开 Rails 日志观察「同一条查询被重复执行 N 次」，或用 bullet gem、Rails 自带的 N+1 查询日志告警；User.includes(:posts).each { |u| u.posts.size } 若变成 1+N 条 SQL 就是典型症状。
  • 解决：用 includes（预加载，按关联自动决定 join 或独立查询）、preload（总用独立查询）、eager_load（强制 LEFT JOIN）在查询主对象时一次性把关联数据取出。计数类可用 counter_cache 避免重复 COUNT。
  • 进阶：深层嵌套用 includes(comments: [:author])；大关联避免一次性加载可用 lazy 或分页；注意 includes 与 where 作用在关联上时可能失效，需改用 preload+references 或显式 joins+select。根本原则：列表页/API 序列化前先想清楚「这条路径会触发哪些 SQL」。
