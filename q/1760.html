Ruby 的内存管理与 GC 是怎样工作的？面对内存上涨/Full GC 频繁该怎么优化？

中级开放讨论题后端开发工程师RubyGC内存优化

题目

考察点：Ruby 的分代 GC（RGenGC）与常见内存问题定位手段，是 Ruby 服务端稳定性的高频考点。

参考答案

要点：

  • 机制：Ruby 2.1+ 使用分代 GC（RGenGC），对象分「新生代/老生代」，新对象先入新生代，存活久的晋升老生代；以标记-清除为主、Minor GC 只扫新生代、Major/Full GC 才扫全堆。还有老生代回收（oldgen）与增量/并发标记降低停顿。GC 统计可用 GC.stat、GC::Profiler。
  • 内存上涨定位：用 ObjectSpace.count_objects/ObjectSpace.each_object 看哪类对象最多；用 memory_profiler、derailed_benchmarks 或 heapdump 找泄漏点（常见是缓存无限增长、全局变量、闭包持有大对象、Nokogiri 等大对象未释放）。
  • 优化：① 减少短命大对象分配（字符串拼接用 <<、避免循环内建大数组）；② 控制缓存大小、用 LRU；③ 调整 RUBY_GC_HEAP_/RUBY_GC_OLDMALLOC_ 环境变量扩大堆或老生代阈值；④ 长期服务用 Puma 的 fork 预加载 + 定期重启 worker 兜底。原则是先测量再调参，别盲调 GC 参数。
