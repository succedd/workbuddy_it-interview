用 SQL 做漏斗和留存分析时，窗口函数和自连接各适合什么场景？如何避免重复计数？

中级场景题业务数据分析师SQL窗口函数漏斗分析留存分析

题目

考察业务数据分析师的 SQL 实战：同一业务问题有多种写法，选错会导致口径错误或性能问题。

参考答案

窗口函数适合

  • 去重取首次/末次行为：ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY ts) 取每个用户的第一步；LAG/LEAD 看相邻事件时间差。
  • 留存：按用户首次活跃日期分组，用 DATEDIFF 标记后续活跃日，再按 cohort 聚合；避免多次自连接。
  • 漏斗：给每个用户的事件打步骤号，MIN(CASE WHEN step=... THEN ts END) 求每步时间，再判断步骤间先后。

自连接适合

  • 需要比较同一用户两个不同事件的时间关系且逻辑简单时；但用户量大时自连接代价高，容易因一对多产生重复行。
  • 多步漏斗用自连接会越写越复杂，优先窗口函数/CTE。

避免重复计数

  • 先明确分析粒度（用户/会话/订单），在子查询里按粒度去重再聚合；不要在明细表上直接 COUNT(*)。
  • 用 COUNT(DISTINCT user_id) 而不是 COUNT(user_id)；多表 join 前先聚合，避免 fan-out。
  • 时间窗口用半开区间 [start, end)，避免边界重复；同一用户同一步骤多次发生只算一次（除非业务定义就是次数）。

性能

  • 大表按分区/日期裁剪，先过滤再开窗；把中间结果落临时表/物化视图；检查执行计划，避免全表扫描和笛卡尔积。
