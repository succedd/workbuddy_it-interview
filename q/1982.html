如何把混沌工程融入 CI/CD 和 SLO 体系，让它成为常态化工程实践而非一次性活动？

高级简答题SRE站点可靠性工程师后端开发工程师云计算工程师混沌工程CI/CDSLOGameDay韧性工程

题目

高级：混沌工程最怕「热闹一阵就荒废」。请讲清怎样把实验沉淀进研发流程，并用 SLO 做护栏与度量。

参考答案

要点：

  • 融入 CI/CD 与发布：在预发/金丝雀阶段把轻量混沌实验作为发布门禁（如每次发布自动跑「杀一个副本 + 网络延迟」验证自愈），用 Chaos Mesh/Litmus 以声明式实验随流水线触发；生产侧则以常态化 GameDay + 定时实验替代一次性活动。
  • 用 SLO 做护栏与判定：把稳态指标直接映射到 SLO/Error Budget——实验期间若 Error Budget 消耗速率异常或 SLI 跌破目标，自动终止实验并告警；用 SLO 把「韧性」从主观感觉变成可度量目标，脆弱点以「消耗预算」量化优先级。
  • 渐进式与组织化：从最小爆炸半径的只读实验起步，逐步扩大；建立实验目录与复盘知识库，把每次证伪的假设变成待修项并追踪；把混沌能力下沉为平台（自助申请实验、统一护栏），降低团队使用门槛。
  • 参考 AWS Builder's Library 的「静态稳定性」「单元格架构」等韧性模式，让混沌实验验证架构假设而非孤立测故障，形成「假设—实验—改进」飞轮。
