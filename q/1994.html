GitHub-hosted runner 与 self-hosted runner 有什么区别？如何安全地使用 self-hosted runner？

中级简答题DevOps工程师SRE站点可靠性工程师后端开发工程师CI/CDrunner安全

题目

简答题：考察两种 runner 的取舍与安全边界，尤其自建 runner 的风险点。

参考答案

要点：

  • GitHub-hosted runner：由 GitHub 提供的临时虚拟机（每次运行全新、用完即销毁），无需运维、干净隔离，但受限于规格、并发配额与单 job 6 小时上限，且处于公网。
  • self-hosted runner：跑在你自己机器/集群上的 agent，适合需要内部网络、特定硬件（GPU、数据库）、私有依赖或更大资源的场景，但复用同一台机器会残留文件/环境变量，隔离性弱。
  • 安全实践：① 不要在 self-hosted runner 上运行不受信任的 fork PR（攻击者可篡改 workflow 偷凭证）——应在 pull_request_target 或用 if: github.event.pull_request.head.repo.full_name == github.repository 限制来源；② 用 --ephemeral 按 job 起一次性 runner，或在每次运行后用干净的容器/镜像；③ 把云凭证、密钥放在 GitHub Encrypted Secrets 或 OIDC 里，绝不写进仓库明文；④ 限制 runner 的网络出口。

核心权衡：hosted 省心但受限，self-hosted 灵活但有隔离与安全责任，必须配合最小权限与一次性环境。
