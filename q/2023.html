题目

某表出现读延迟飙升、SSTable 数量膨胀，怀疑是墓碑（tombstone）堆积或大分区导致，应如何定位与治理？

参考答案

要点：

  • 定位墓碑堆积：大量 DELETE/TTL 过期会产生 tombstone，Compaction 未及时清理时，读请求会扫描大量带墓碑的 cell 并触发 ReadRepair。用 nodetool tablestats 看 tombstones 数、nodetool cfstats，并在日志中关注 Read 1000 tombstones 类告警；也可 SELECT 配合 TTL/writetime 排查。
  • 定位大分区：nodetool cfstats 的 Compacted partition maximum bytes 或 sstablemetadata 查看单分区大小；大分区会让单条读拖垮节点。
  • 治理手段：① 调 gc_grace_seconds 与 Compaction 策略（如 TimeWindowCompactionStrategy 对时间序列数据更友好），加速墓碑回收；② 对大分区做 分桶重建模（见上题）；③ 控制批量删除、用 UNLOGGED BATCH 替代大规模 DELETE，必要时对历史数据做 nodetool garbagecollect 或重建表。

补充：监控上应把『单分区大小、SSTable 数、tombstone 扫描数、p99 读延迟』纳入告警；治理 tombstone 的核心原则是『让墓碑在 Compaction 中尽快被物理清除』，而不是无限堆积。
