百度百舸开发机 SSH 连接超时，服务端一切正常，只有 BLB 内网地址，客户通过专线和跨地域对等连接访问，怎么排查？

中级故障排查题公有云售后技术支持网络运维工程师SRE站点可靠性工程师百度百舸开发机SSHBLB对等连接专线

题目

场景：北京地域的百舸开发机（Isaac Lab 3.0.0 镜像，约 16.7GB）启动后，用户 SSH 报 Connection timed out。检查结果：Pod 已 Ready、重启 0 次；sshd 正常监听 22 端口，host key 与 authorized_keys 正常，sshd 日志里没有任何用户连接记录；LoadBalancer Service 和 BLB 同步成功，Endpoints 就绪；BLB 只有 10.x 内网 VIP，没有公网 IP，也没有绑定 EIP；控制台显示 SSH 接入端口为 1535（映射到容器 22 端口）。客户实际网络链路为：苏州办公网 → 专线 → 苏州火山云 → 10G 云间互联 → 苏州百度云 VPC → 跨地域对等连接 → 北京百度云 VPC（开发机 BLB 所在）。请说明排查思路、最可能的根因和解决方案。

参考答案

内容深度：详细 · 无代码示例 · 来源：外部链接 · 未复核 · 近 7 天更新

先给结论

  • 服务端没有问题：Pod Ready、sshd 在监听、BLB 和 Endpoints 都正常，而且 sshd 日志里没有用户连接，说明请求在到达开发机之前就丢了，问题在网络链路。
  • 开发机没有公网 IP 和 EIP，唯一入口是 BLB 内网 VIP。公网或没打通内网的办公网访问，一定会超时。
  • 客户端不一定要和 BLB 在同一个 VPC。只要客户端网络到 VIP 有路由、回程也通即可，同 VPC、对等连接的 VPC、通过专线或 VPN 有路由的网络都可以。

本例最可能的根因：链路是串起来的

  • 实际路径是：苏州办公网 → 专线 → 苏州火山云 → 云间互联 → 苏州百度云 VPC → 对等连接 → 北京百度云 VPC。
  • 对等连接通常只负责两个 VPC 之间互通，不会把专线那一端的流量继续转发到第三个网络。所以苏州 VPC 里的机器能访问北京，机房却可能到不了。
  • 这是基于常见云网络设计的推断，需要用分段测试和路由表核实，并以百度智能云 VPC 文档中对等连接的路由说明为准。

先排除的简单问题

  • 端口：SSH 要连控制台给出的接入端口（本例为 1535），不是容器内的 22。
  • 时间：大镜像拉取需要几分钟，Pod Ready 之前 Endpoints 没就绪，这段时间连接也会超时。启动时出现一次 Startup probe failed 属于探针早于服务就绪，Pod 随后 Ready 就与本问题无关。
  • 访问策略：BLB 没绑安全组时要确认「默认放通」已开启；安全组和 ACL 要放行客户端网段访问接入端口。

分段测试，找出断在哪一段

  • 第一步：在北京 VPC 内找一台机器连 VIP 的接入端口，应该能通，用来确认开发机和 BLB 本身没问题。
  • 第二步：在苏州 VPC 内的机器上连。能通，说明对等连接和两边路由正常。
  • 第三步：从客户机房连。只有这一步不通，基本可以确定是专线和对等连接之间没有转发。
  • 每一步都用 ssh -vvv -p <接入端口> root@<VIP>、nc -vz <VIP> <接入端口> 和 traceroute 看卡在哪一跳。

核对路由

  • 北京 VPC 路由表里，要有回到苏州 VPC 和客户机房网段的路由；只有去程没有回程，同样表现为超时。
  • 专线网关和机房侧，要有到北京 VPC 网段的路由。
  • 机房、苏州 VPC、北京 VPC 三段地址范围不能重叠。

客户实际网络链路

  • 客户提供的拓扑：苏州办公网经核心交换机，通过约 10G 专线接入苏州火山云；火山云是多云互联中心，同时连着阿里云（100G）和苏州百度云（10G）；苏州百度云 VPC 再通过跨地域对等连接到北京百度云 VPC。
  • 这条链路一共四段，中间经过两种不同的互联：火山和百度之间是云间互联，苏州和北京之间是 VPC 对等连接。每多一段，就多一处去程和回程路由要配。
  • 容易误判的地方：百度侧通告给火山的是一个大网段（10.x.0.0/16），它同时覆盖苏州 VPC 和北京 VPC。所以火山和办公网都会把去北京的流量送进苏州百度云，办公网侧“看起来有路由”，但苏州百度云不一定会把这部分流量再转进对等连接。
  • 对等连接一般只转发两个 VPC 自己之间的流量，不承接从云间互联进来的第三方流量。这是推断，需要按下面的步骤核实，以百度智能云文档和控制台路由为准。
  • 核对点一：对等连接两端的路由里，是否加了办公网网段和火山侧网段。
  • 核对点二：北京 VPC 路由表里，是否有回办公网、回火山网段的路由，并指向对等连接。只有去程没有回程，表现同样是超时。
  • 核对点三：苏州百度云的云间互联或专线网关，是否把去北京网段的流量指向对等连接。
  • 分段测试按北京 → 苏州百度云 → 火山云 → 办公网的顺序往回测，第一处不通的地方就是断点。
  • 如果确认对等连接不能转发这类流量，可选方案有三个：用云智能网（CSN）把云间互联、苏州 VPC、北京 VPC 接入同一张网；在苏州百度云放跳板机中转；或者把开发机直接建在苏州地域。

对等连接配置核对（控制台截图要点）

  • 客户的对等连接为「非跨境、本帐号」类型：本端华北-北京 VPC（示例网段 10.x.20.0/22），对端华东-苏州 VPC（示例网段 10.x.0.0/22），按使用流量计费，带宽上限 10000Mbps。
  • 两端网段不重叠，满足建立对等连接的前提；开发机 BLB 的内网 VIP 落在北京 VPC 网段内，所以苏州 VPC 内的机器理论上可以直达。
  • 对等连接只负责这两个 VPC 之间互通。机房流量从专线进入苏州 VPC 后，不会自动经对等连接转发到北京，这是需要用路由核实的推断，以百度智能云对等连接文档为准。
  • 在对等连接详情里打开「编辑对等连接路由」，确认本端和对端是否加了机房网段；再核对北京 VPC 路由表回程、专线网关到北京网段的路由。
  • 如果控制台不支持把机房网段经对等连接转发，就改用云智能网（CSN）统一互联，或者先登录苏州 VPC 的跳板机再访问开发机。
  • 带宽上限和按流量计费只影响速度和费用，不会造成 SSH 连接超时，排查时可以先不看。

解决方案

  • 推荐：用云智能网（CSN）把专线、苏州 VPC、北京 VPC 接入同一张网，由 CSN 统一学习和下发路由，解决跨地域加专线的转发问题。
  • 临时办法：在苏州 VPC 里放一台跳板机，客户先登录跳板机，再访问北京的开发机。
  • 安全规范允许时，可为开发机开启公网访问或绑定 EIP，并用安全组限制来源 IP。
  • 以后新建开发机时，直接选择专线已经能直达的 VPC 和地域。

预防

  • 创建开发机前先确认访问方式：公网、同 VPC，还是经专线访问，并提前打通路由。
  • 固定使用控制台给出的完整 SSH 命令，避免把容器端口和接入端口混淆。
  • 大镜像先转存到国内仓库，缩短启动时间；状态变成「运行中」后再连接。
