服务器常见硬件故障

中级开放讨论题硬件工程师系统运维工程师云计算工程师公有云售后技术支持·云基础设施的日常运维

题目

服务器常见硬件故障

参考答案

服务器硬件故障，最常见的就是某个部件坏了导致机器不稳定、宕机或者报警。

在公有云售后支持这个岗位，你一般不需要亲自换硬件（机房/厂商会做），但需要能看报警、能判断大概故障点、能提报修工单。

所以重点是：故障现象、怎么发现、怎么处理。

1. 常见硬件故障分类

按服务器的主要部件来划分：

| 硬件部件 | 常见故障 | 典型现象（症状） | 如何发现（排查） | 售后支持怎么处理？ |

|---|---|---|---|---|

| CPU | 过热、CPU内部错误（MCE） | 系统突然宕机、重启、dmesg 出现 Machine Check Exception 报错 | dmesg、BMC 的 SEL 日志（带外日志） | 带外有 CPU 相关报警就直接报修（记录 SN、槽位等信息） |

| 内存（内存条） | ECC 错误、接触不良、内存条损坏 | 随机重启、应用崩溃、系统卡顿。dmesg 有 EDAC、Uncorrected ECC 报错 | dmesg、BMC 日志、带外硬件监控报警 | 非常常见。看到内存 ECC 报警 → 记录故障信息 → 提交硬件报修 |

| 硬盘（HDD/SSD/NVMe） | 掉盘、坏道、寿命预警（SMART 预警） | RAID 降级（Degraded）、I/O 超时、读写报错、磁盘无法识别 | smartctl -a、RAID 管理工具（如 storcli、megacli）、dmesg（I/O error） | 预测性故障（Pre-fail）：提前报修；掉盘（Failed）：优先报修，且要关注 RAID 状态 |

| RAID 控制器 | RAID 卡故障、缓存故障、BBU（电池）失效 | RAID 组异常、写入变慢、带外报警（缓存写保护） | RAID 管理工具日志、BMC SEL 日志 | 这类报警一般不靠重启能解决，直接报修 |

| 主板 | PCIe 总线错误、VRM（供电）异常、南桥故障 | 无法开机（亮灯但不自检）、带外（BMC/IPMI）突然失联、频繁莫名重启 | BMC 无法登录、BMC SEL 有大量总线类报错 | 主板类故障判断难，但如果带外都连不上、且重启无效，很大概率是主板或供电问题 → 优先报修 |

| 电源（PSU） | 电源模块故障、供电异常 | BMC 报警（PSU 故障/冗余丢失）、机器突然断电再重启 | BMC 传感器、带外硬件报警 | 服务器一般是双电源冗余的。如果报 PSU Failed 或 Redundancy Lost，机器可能还在跑，但必须报修 |

| 风扇/散热 | 风扇停转、转速过低 | 温度报警（CPU/主板温度过高）、过热保护自动关机 | BMC 传感器（ipmitool sensor）、带外温度报警 | 风扇坏 → 散热出问题 → 可能触发过热关机保护。这种是高优先级报修 |

| 网卡（NIC） | 网卡掉线、PCIe 错误、端口故障 | 网络突然中断、丢包严重、dmesg 出现 NIC link down、PCIe AER 报错 | dmesg、ethtool、BMC 日志 | 先排查网线（光模块/网线接触），如果排除线缆还是报错 → 报修网卡 |

| GPU（GPU 服务器） | 过热、显存 ECC 错误、掉卡 | AI 训练/推理任务中断、nvidia-smi 报错、驱动报错、BMC 有 GPU 温度报警 | nvidia-smi、dmesg、BMC 硬件报警 | GPU 服务器很常见（尤其是跑大模型）。看到显存错误、温度过高、设备掉卡这类，一般直接走硬件报修 |

| 背板/线缆（SAS/背板） | 背板接触不良、SAS 线缆松动 | 硬盘突然全部消失、RAID 卡识别不到盘、间歇性掉盘 | dmesg（SAS link error、phy error 等） | 比较容易误判成硬盘坏。排查时会先怀疑线缆，再报修背板 |

2. 按严重程度划分（工作中很实用）

在售后支持值班时，优先级特别重要：

| 优先级 | 故障类型 | 处理建议 |

|---|---|---|

| P0（最高） | 机器宕机、无法开机、带外失联、过热自动关机 | 立即排查（EVA/VNC 登录尝试）、第一时间报修、同步客户进展 |

| P1 | RAID 降级（掉盘）、双电源冗余丢失（Redundancy Lost）、网卡全部中断 | 业务可能没立刻中断，但有单点风险，优先报修 |

| P2 | 单个风扇转速低、SMART 预测性预警（Pre-fail）、ECC 少量报错 | 还在跑，但有风险。记录、报修、观察监控是否继续恶化 |

3. 售后支持最关心的“信号”

你平时做这个岗位时，最能直接判断是硬件故障的报警信号：

  • BMC/带外报警：这是云厂商最先推送的硬件报警（温度、风扇、电源、硬盘等）
  • dmesg 出现 error、failed、timeout：尤其是 I/O error（磁盘）、MCE（CPU）、PCIe（总线）
  • RAID 状态变化：从 Optimal 变成 Degraded（降级）或 Failed
  • 带外（IPMI/VNC）突然登录不上：系统能挂，但带外都登不上，大概率是硬件层面问题

4. 面试怎么回答？

推荐的简洁回答（能直接用）：

服务器硬件故障主要集中在几个部件：内存（ECC 报错）、硬盘（掉盘、SMART 预警导致 RAID 降级）、电源（PSU 故障、冗余丢失）、风扇（转速异常引起温度过高）、CPU（过热或 MCE）、主板/RAID 卡（总线、缓存故障）等。
作为售后技术支持，我的职责不是修硬件，而是：根据监控报警和系统日志（如 dmesg、BMC 日志）初步判断故障类型 → 收集关键信息（服务器 SN、故障部位、报错信息） → 提交硬件报修工单 → 跟进维修进度 → 必要时配合做 EVA 重启、确认业务恢复。

这段话特别贴合你这个岗位的 JD，面试官听起来会很有“业务感”。
