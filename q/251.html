Android 的 Handler、Looper、MessageQueue 是如何协作实现线程通信的？

题目

Android 的 Handler、Looper、MessageQueue 是如何协作实现线程通信的？

参考答案

结论

三者构成 Android 的消息循环机制，是跨线程通信与 UI 刷新的基石。

  • MessageQueue：按执行时间排序的单链表，存放待处理 Message。
  • Looper：每个线程最多一个（通过 ThreadLocal 绑定）；Looper.loop() 进入无限循环，调用 MessageQueue.next() 取消息；无消息时通过 nativePollOnce 阻塞休眠（基于 epoll），不空转耗 CPU。
  • Handler：创建时绑定某个 Looper；发送消息（sendMessage/post）实际把 Message 入队到该 Looper 的 MessageQueue（Message.target 指向发送它的 Handler）；Looper 取出消息后调用 msg.target.dispatchMessage() 回到 Handler 的 handleMessage 处理。

主线程（ActivityThread）启动时已自动创建并启动 Looper，因此主线程可直接用 Handler。典型用法：子线程完成耗时任务后用主线程 Handler 把结果 post 回主线程更新 UI。

内存泄漏提醒：非静态内部类 Handler 会隐式持有外部 Activity，再配合延时消息极易泄漏；推荐静态内部类 + WeakReference，并在 onDestroy 中调用 removeCallbacksAndMessages(null)。
