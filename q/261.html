客户反馈 Linux 云服务器 SSH 无法登录，按概率排序的排查路径是什么？

中级故障排查题公有云售后技术支持云计算工程师ECSSSH安全组VNC故障定位

题目

客户在工单中反馈：某台 Linux ECS 突然 SSH 连不上，业务中断。请给出从云平台侧到系统内部的排查路径，并说明如何用 VNC 登录做第一层隔离。

参考答案

排查路径

  1. 先查资源状态：控制台确认 ECS 是否为「运行中」（被冻结、关机都会导致无法登录）；确认是否绑定弹性公网 IP（未绑定 EIP 则无法公网 SSH 登录，也影响 RDP/MSTSC 方式）。
  2. 用 VNC 做第一层隔离：通过控制台「远程登录」（VNC 方式）测试。VNC 能进 → 云平台网络链路基本正常，故障集中在安全组/防火墙/OS 内部/客户端网络；VNC 也进不去 → 优先怀疑平台侧资源状态或平台故障，记录资源 ID 与故障时间后提单。
  3. 常见原因（按概率排序）：① 资源被冻结/停止；② 用户名或密码错误（Linux 默认 root，忘记密码可在控制台重置并重启生效；密钥对方式首次登录用 SSH 密钥）；③ 负载过高（CPU/带宽利用率过高会导致无法登录）；④ 未绑定 EIP；⑤ 运营商/ISP 拦截（换手机热点测试）；⑥ 防火墙拦截；⑦ 安全组未放通 22 端口或远程访问端口配置异常；⑧ 配置了 SSH 登录 IP 白名单（启用企业主机安全 HSS 后常见）；⑨ 操作系统内部原因（文件系统损坏等）；⑩ 第三方杀毒软件拦截。
  4. VNC 可登而 SSH 不可时，重点核对：安全组入方向 22 端口、sshd 服务状态与配置、防火墙规则、SSH 白名单；有报错信息时按报错提示逐条对照处理。
