编写 Dockerfile 时有哪些最佳实践可以减小镜像体积、加快构建速度？

中级场景题DevOps工程师系统运维工程师Dockerfile多阶段构建镜像优化构建缓存

题目

考察点：多阶段构建、精简基础镜像（alpine/distroless）、合理利用构建缓存层、.dockerignore、合并 RUN 减少层数、非root 运行等。属场景题。

参考答案

要点：

  • 多阶段构建（Multi-stage）：编译阶段用含工具链的大镜像，最终阶段只 COPY 编译产物到极小运行时镜像（如 golang:alpine → scratch），彻底剔除构建依赖，镜像可缩小数倍。
  • 精简基础镜像：优先 alpine、distroless 或 scratch，避免 ubuntu/centos 全家桶。
  • 利用构建缓存：把变动少的指令（如装依赖）放前面、COPY 源码放后面；RUN apt-get update && install && clean 写在同一层避免缓存膨胀；这样代码改动时前面的层可命中缓存，显著加速重建。
  • .dockerignore：排除 .git、本地 node_modules、构建产物等，避免无谓打入上下文、减小传输与层大小。
  • 减少层数 & 清理：合并相关 RUN；安装后清理包管理器缓存（apt-get clean、rm -rf /var/lib/apt/lists）。
  • 安全与规范：用 USER 切换到非 root 运行；CMD 用 exec 形式；固定基础镜像 tag/digest 保证可复现。
