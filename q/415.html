服务频繁 Full GC 甚至抛出 OutOfMemoryError，如何区分是「堆溢出」「元空间溢出」还是「直接内存/堆外溢出」？各自的排查手段是什么？

中级故障排查题Java后端工程师系统运维工程师OOMFullGC元空间直接内存故障排查

题目

考察点：不同 OOM 的异常信息（Java heap space / Metaspace / Direct buffer memory）对应不同区域；排查工具与启动参数各异。属故障排查题。

参考答案

看异常信息一眼区分

  • java.lang.OutOfMemoryError: Java heap space → 堆（对象太多/太大，GC 回收不掉）。
  • ...: Metaspace（或 PermGen）→ 类元数据区，常因动态生成类（CGLIB、Groovy、反射、ClassLoader 泄漏）撑爆。
  • ...: Direct buffer memory → 堆外直接内存（Netty/NIO 的 ByteBuffer.allocateDirect），受 -XX:MaxDirectMemorySize 限制。
  • ...: unable to create new native thread → 线程数到上限（ulimit/内存），非堆问题。
  • ...: GC overhead limit exceeded → 98% 时间做 GC 却只回收 2% 内存，典型泄漏前兆。

各自治法

  • 堆溢出：按上题 jmap+MAT 找大对象/泄漏；调大 -Xmx 只是缓解，根因仍是引用未释放。
  • 元空间溢出：加 -XX:MaxMetaspaceSize，用 -verbose:class / jstat -class 看类加载数；排查 ClassLoader 泄漏（热部署未卸载）。
  • 直接内存溢出：加 -XX:MaxDirectMemorySize，用 NMT（-XX:NativeMemoryTracking=detail + jcmd <pid> VM.native_memory）看堆外分布；检查 Netty 池化 ByteBuf 是否未释放。
  • 通用：保留 -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/path 自动留档。
