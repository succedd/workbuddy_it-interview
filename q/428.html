如何用 jstack / Arthas 定位 Java 死锁？请给出一个『两个线程互相等待对方持有的锁』的实际排查步骤；死锁的四个必要条件与常见避免手段是什么？

中级场景题Java后端工程师死锁jstackArthas加锁顺序Java并发

题目

考察点：死锁定位工具（jstack 直接报 deadlock、Arthas thread -b）、死锁四要件、预防（顺序加锁/超时/检测）。属场景题。

参考答案

排查步骤

  • ① 抓线程栈：jstack <pid>，输出末尾 JVM 会直接打印『Found one Java-level deadlock』并指出互相等待的线程与锁；或 Arthas thread -b 直接列出阻塞源。
  • ② 看锁持有链：找到线程 A 持有 lock1 等 lock2、线程 B 持有 lock2 等 lock1 的成环关系，确认死锁。
  • ③ 定位代码：按 nid/栈帧找到对应 synchronized 代码行，确认加锁顺序。

死锁四必要条件（全满足才死锁）

  • 互斥、持有并等待、不可剥夺、循环等待。

避免手段

  • 固定加锁顺序：所有线程按同一全局顺序获取多把锁（打破循环等待），最常用。
  • 超时获取：用 tryLock(timeout)（ReentrantLock）拿不到就放弃/回退，避免永久等。
  • 死锁检测：依赖 JVM/监控周期性 jstack 巡检，告警后自动摘流量。
  • 减小锁粒度 / 用无锁结构：能用并发容器/原子类就不用显式多锁。

口诀：顺序加锁破循环、超时回退防久等。
