Argo CD 如何控制一批资源的上线顺序？Sync Phases（Hook）与 Sync Waves 有什么区别，如何配合使用？

中级简答题CI/CD工程师平台工程师ArgoCDGitOps同步编排

题目

用 Argo CD 部署应用时，需要先跑数据库迁移、再发应用、最后做冒烟验证。请说明同步阶段与同步波次的机制、排序规则，以及裁剪（prune）时的顺序特点。

参考答案

一、Sync Phases：粗粒度的阶段编排

通过注解 argocd.argoproj.io/hook 把资源标记为某个阶段，Hook 通常是 Pod、Job 或 Argo Workflow：

  • PreSync：在应用 manifests 之前执行，任一失败则整个同步终止（适合做前置检查、数据库迁移）。
  • Sync：所有 PreSync 成功之后、与应用 manifests 同时执行。
  • PostSync：同步成功且所有资源进入 Healthy 之后执行，适合冒烟测试与通知。
  • SyncFail：同步失败时执行，用于清理与告警。
  • Skip：Argo CD 跳过该资源（常用于绕开 Helm chart 里有问题的 hook）。

Hook 的清理由 argocd.argoproj.io/hook-delete-policy 决定：HookSucceeded、HookFailed、BeforeHookCreation（不指定时的默认行为，创建新 hook 前先删掉旧的）。

二、Sync Waves：阶段内的精确排序

用注解 argocd.argoproj.io/sync-wave: "5" 指定波次，值为整数，默认 0，可以是负数（例如把 DB 迁移 Job 放在 -1，保证跑在所有资源之前）。

完整排序优先级：阶段（phase）→ 波次（由小到大）→ 资源 kind（Namespace 优先，然后是其它内置资源，最后是 CRD）→ 名称。

两个关键行为：

  1. 同步时先找到第一个存在「不同步或不健康」资源的波次，应用它，然后重复该过程直到全部波次同步且健康。这意味着如果第一个波次里的资源永远不健康，整个应用就永远到不了 Healthy。
  2. 每两个波次之间有约 2 秒延迟（可用环境变量 ARGOCD_SYNC_WAVE_DELAY 调整），目的是给其它控制器（如 Deployment 控制器）反应时间，避免 Argo CD 拿着旧对象状态过早判定健康、过早触发 Hook。

三、裁剪时顺序相反

开启 prune 时，波次顺序会反转：波次号大的先删，且任一波次删除失败即停止，不会继续删除更低波次，从而保证「先删依赖方、后删被依赖方」。

四、注意

Hook 不会在选择性同步（selective sync）中执行；SyncFail Hook 自身失败时，Argo CD 只会把整体操作标记为失败，不会再做额外动作。
