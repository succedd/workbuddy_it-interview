编程题：写出下面代码在浏览器中的完整输出顺序，并解释每一步为什么。 ```js console.log('start'); setTimeout(() => console.log('timeout'), 0); Promise.resolve().then(() => console.log('promise1')); queueMicrotask(() => console.log('micro')); console.log('end'); ```

中级编程题前端开发工程师事件循环输出顺序setTimeoutPromisequeueMicrotask

题目

考察点：能否把「同步代码 → 微任务队列清空 → 下一个宏任务」的调度模型应用到具体代码上。追问：如果把 setTimeout 的延迟改成 0，它能先于 Promise 执行吗？

参考答案

要点：输出顺序为 start → end → promise1 → micro → timeout。

  • 第一轮（同步）：整段脚本作为一个宏任务执行，console.log('start')、console.log('end') 直接入栈执行，先行输出。
  • 入队时机：setTimeout 的回调（0ms 后）进入任务队列；Promise.resolve().then 与 queueMicrotask 的回调进入微任务队列。注意：登记 ≠ 执行。
  • 第二轮（排空微任务）：同步代码结束、栈空，事件循环清空微任务队列——按入队顺序执行 promise1、micro。
  • 第三轮（宏任务）：微任务队列已空且渲染机会过后，才取出 setTimeout 的回调输出 timeout。即使 delay 为 0，宏任务也必须等本轮微任务全部清空，且 0ms 只是「最早可用时机」而非立即执行。
  • 常见误区：认为 setTimeout(fn, 0) 比 Promise.then 快——错在把「先登记」当成了「先执行」，队列优先级才是决定因素。
