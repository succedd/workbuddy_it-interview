场景题：你的图片加载函数有两条路径——缓存命中时直接赋值并触发 load 事件（同步），未命中时走 fetch().then()（异步）。QA 反馈「有时调用结束后 data 属性还没设置」。如何修复，使两条路径的时序完全一致？

中级场景题前端开发工程师queueMicrotask时序一致性Promise工程实践

题目

考察点：微任务的工程化价值——用 queueMicrotask 平衡同步/异步分支的执行顺序。追问：为什么不直接把同步分支改成 setTimeout(fn, 0)？

参考答案

要点：在同步分支中用 queueMicrotask() 包裹赋值与触发逻辑，让两个分支都变成「微任务级」延迟，时序即完全一致。

  • 问题根因：缓存命中走同步路径（数据赋值、load 事件在调用返回前就完成），未命中走 Promise（赋值发生在微任务里）。调用方在两种情况下观察到的状态不同，甚至出现「函数刚返回时 data 未设置」的竞态。
  • 修复方式：
function loadImage(url) {
  if (cache.has(url)) {
    queueMicrotask(() => {
      img.dataset.src = cache.get(url);
      img.dispatchEvent(new Event('load'));
    });
  } else {
    fetch(url).then(data => {
      cache.set(url, data);
      img.dataset.src = data;
      img.dispatchEvent(new Event('load'));
    });
  }
}
  • 为什么不用 setTimeout(fn, 0)：宏任务会被事件处理、渲染、其他 timeout 插队，延迟不可控且可能晚于调用方注册的其他回调；微任务保证在「当前脚本退出后、任何下一个任务之前」执行，是最小且确定的延迟。
  • 通用原则：任何「同一操作可能同步也可能异步完成」的 API（缓存、本地存储、幂等请求）都应统一到微任务时序，避免调用方写两套处理逻辑。
