HTTPS / TLS 是如何保证通信安全的？RSA 与 ECDHE 握手有何区别？

高级简答题HTTPSTLS加密证书

题目

HTTPS 如何解决明文传输的窃听、篡改、冒充三大风险？请说明混合加密、摘要/签名、数字证书的作用，并对比 RSA 与 ECDHE 密钥交换。

参考答案

HTTPS = HTTP over TLS，在 TCP 与应用层间加安全层，提供机密性、完整性、身份认证三保障。

1. 混合加密（解决窃听）：握手阶段用非对称加密交换“会话密钥”，之后全程用对称加密（如 AES-GCM）传输数据。对称加密快，非对称仅用于协商密钥。

2. 摘要 + 数字签名（解决篡改与冒充）：对内容做哈希得到“指纹”，服务端用私钥对指纹加密即数字签名；客户端用公钥解密比对，既验证完整性又证明来源。

3. 数字证书（解决公钥可信）：服务器公钥由 CA 签发证书（含域名、公钥、CA 签名）。客户端用内置 CA 根公钥验证证书链，确认公钥确实属于该域名，防中间人伪造。

TLS 握手（TLS 1.2 典型四步）：ClientHello（版本/随机数/密码套件）→ ServerHello+证书 → 客户端校验并发送 pre-master（RSA 用服务器公钥加密；ECDHE 发公钥）→ 双方用三个随机数派生会话密钥 → Finished。

RSA vs ECDHE 区别：

  • 前向安全（Forward Secrecy）：RSA 不支持（服务器私钥泄露则历史通信可被解密）；ECDHE 每次用临时密钥，支持前向安全。
  • 流程：ECDHE 在 ServerHello 后多一个 Server Key Exchange 消息；RSA 没有。
  • 效率：ECDHE 允许客户端提前发加密数据（少一个 RTT）。现代 TLS 1.3 默认采用 ECDHE。
