某进程 CPU 使用率突然飙到 100%+，如何一步步定位到具体热点函数？

中级故障排查题系统运维工程师DevOps工程师CPUperf火焰图热点函数on-CPU

题目

考察点：CPU 火焰图的完整排查链路（top→mpstat→pidstat→perf→火焰图），以及 on-CPU 与 off-CPU 的区别。追问：如果 CPU 利用率不高但进程依然很慢，该怎么查？

参考答案

排查链路（on-CPU 热点）：

  1. top -H 或 top 找到高 CPU 的进程 / 线程 PID、TID；
  2. mpstat -P ALL 1 确认是单核还是多核打满，排除「平均低但单核 100%」的假象；
  3. pidstat -u -p <pid> 1 看该进程用户态 / 内核态拆分；
  4. perf top -F 49 -p <pid> 实时看热点符号；
  5. 抓样本：perf record -F 99 -a -g -- sleep 30 再 perf report；
  6. 生成火焰图：perf script | ./stackcollapse-perf.pl > out.folded && ./flamegraph.pl out.folded > cpu.svg，纵向找最宽的栈帧即热点函数。

关键区分：

  • on-CPU 高（us / sy 高）→ 用上面链路找计算热点；
  • off-CPU 高（进程在等锁 / IO / 网络，CPU 不高却慢）→ 用 off-CPU 火焰图（perf sched / 调度延迟），此时只看 CPU 利用率会误判为「CPU 没问题」。

注意：容器里 top 可能显示宿主机核数导致误读，应结合 cat /sys/fs/cgroup/cpu/cpu.cfs_quota_us 或 cgroup 视角确认配额后再下结论。
