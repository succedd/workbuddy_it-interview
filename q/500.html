free 显示 available 很低，如何判断是会 OOM 还是缓存可回收？内存泄漏 / OOM 怎么定位？

中级故障排查题系统运维工程师DevOps工程师内存OOMfreevmstatswap

题目

考察点：free 的 available 与 free 区别、swap 颠簸 si/so 判据、OOM 从 dmesg 找凶手。追问：available 低但 free 高，需要紧张吗？

参考答案

要点：

  1. free 看 available 而不是 free：available = 估算可用于启动新进程的内存（含可回收 page cache），free 只是完全空闲部分；available 低但 free 高通常是缓存占着，属正常，无需恐慌。
  2. swap 颠簸才是真危险：vmstat 1 看 si / so（每秒换入 / 换出），持续 > 0 说明内存真的不够、在和磁盘来回倒腾，延迟会陡增；sar -r 1 看 kbmemfree / kbmemused / %commit。
  3. 定位内存大户：top 按内存排序（M）、pidstat -r、或 pmap -x <pid> 看进程映射中哪段匿名内存 / 堆在涨，据此判断泄漏点。
  4. OOM 找凶手：dmesg -T | grep -i 'out of memory' 或 /var/log/messages 中有 Killed process <pid> (xxx)，包含 oom_score_adj 与占用内存，定位被杀死的进程；再用 cat /proc/<pid>/status 的 VmRSS 复盘。

结论：available 低先确认 si / so 与 cache 回收情况，再查具体进程增长曲线；只有 %commit（已承诺内存）逼近内存上限且持续 swap 才真正逼近 OOM。
