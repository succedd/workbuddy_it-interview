服务出现 TCP 重传和连接超时，如何用 sar / ss 判断是网络抖动还是本机问题？

高级故障排查题系统运维工程师DevOps工程师网络TCP重传sarss性能排查

题目

考察点：TCP 重传率、丢包、连接队列（Recv-Q / Send-Q）、缓冲区，高级网络性能定位。追问：本机 Send-Q 持续堆积 vs sar 重传高但本机 rtt 正常，分别指向什么？

参考答案

要点：

  1. 看整体网络健康（sar -n）：

- sar -n DEV 1：rxpck/s、txpck/s、rxkB/s、txkB/s 看流量；rxerr/s、txerr/s、coll/s、rxdrop/s 非零即错误 / 丢包；

- sar -n ETCP 1：retrans/s（TCP 重传速率）是关键，持续 > 0 说明有丢包或拥塞；estres/s、atar/s 看新建 / 失败连接。

  1. 看本机 socket 状态（ss）：

- ss -anti：-n 不解析、-t TCP、-i 看 TCP 内部信息；重点看 Recv-Q / Send-Q（积压未读 / 未确认数据，持续大 = 对端收不动或本机发送阻塞）、retrans（重传次数）、rtt / cwnd；

- ss -lnt 看 listen 套接字 Send-Q（accept 队列）是否满，满了会丢新连接（配合 netstat -s 的 TCPBacklogDrop）。

  1. 判定链路：重传 + 丢包在 sar -n ETCP 高但本机 ss 的 rtt 正常 → 多半是中间网络 / 对端抖动；若本机 Send-Q 持续堆积 → 是本机应用处理慢或 accept 队列满。

进阶：用 tcpdump / tcpretrans（bcc）抓重传样本，结合 ethtool -S <eth> 看网卡层面 discards / errors，逐层收敛。
