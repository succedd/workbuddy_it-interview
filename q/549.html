SQL 注入的原理是什么？为什么拼接 SQL 是危险的？

初级简答题SQL注入Web安全漏洞原理

题目

请结合示例说明 SQL 注入是如何发生的，以及为什么将用户输入直接拼接到 SQL 语句中会破坏“代码与数据”的边界。

参考答案

原理：当程序把用户可控输入直接拼接到 SQL 字符串、而非作为“数据”参数对待时，输入内容会被数据库当作 SQL 代码执行，从而改变原有语句的语义。

危险示例（字符串拼接）：

String sql = "SELECT * FROM users WHERE name = '" + name + "' AND pwd = '" + pwd + "'";

若用户输入 name = admin' --，语句变为：

SELECT * FROM users WHERE name = 'admin' --' AND pwd = ''

-- 之后被注释，攻击者无需密码即以 admin 登录。更危险的可拼接 '; DROP TABLE users; -- 造成破坏。

根因：拼接混同了“SQL 指令”与“用户数据”，数据库无法区分二者。正确做法是用参数化查询把数据边界固化（见下题）。
