浏览器从输入 URL 到页面渲染经历了哪些阶段？请说明关键渲染路径（解析/布局/绘制）。

中级简答题前端开发工程师HTML/CSS/JS工程师页面重构工程师浏览器渲染关键渲染路径DOMCSSOM

题目

请描述浏览器渲染一个页面所经历的主要流程，重点说明关键渲染路径（Critical Rendering Path）中的几个阶段：解析 HTML/CSS、构建 DOM/CSSOM、生成渲染树、布局（Layout）、绘制（Paint）与合成（Composite），并指出 script 和 CSS 在流程中的阻塞关系。

参考答案

整体流程：导航（DNS→TCP→TLS）→ 响应（下载 HTML）→ 解析 → 渲染。

关键渲染路径（CRP）：

  1. 解析 HTML 构建 DOM 树：浏览器将 HTML 字节流词法分析、构建文档树。<script>（无 async/defer）会阻塞 HTML 解析；预加载扫描器会提前请求 CSS/JS/图片等资源。
  2. 解析 CSS 构建 CSSOM 树：CSS 规则转换为样式映射，并级联计算出每个节点的计算样式。等待 CSS 不会阻塞 HTML 解析，但会阻塞后续 JS 执行。
  3. 合成渲染树（Render Tree）：合并 DOM 与 CSSOM，只包含可见节点（display:none 的不包含，visibility:hidden 包含）。
  4. 布局（Layout / Reflow）：计算渲染树中每个节点的几何信息（大小、位置）。首次计算叫布局，后续重新计算叫重排。
  5. 绘制（Paint）：将每个节点转为屏幕像素（文本、颜色、边框、阴影等）。
  6. 合成（Composite）：将不同图层按正确顺序合并到屏幕（如 opacity、transform、will-change 会提升为独立图层，在 GPU 上合成）。

阻塞要点：JS 会阻塞解析（除非 async/defer）；CSSOM 未就绪会阻塞 JS 执行；首屏渲染依赖 14KB 关键 CSS/HTML。优化方向是减少 CRP 长度、尽早下载关键资源、合理使用 async/defer。
