如何撤销 Git 中的修改？reset、revert、checkout 有什么区别？

初级简答题resetrevertcheckout撤销修改

题目

工作区改错、暂存区加错、或已经提交但想撤销，分别该用什么命令？请区分 git reset、git revert、git checkout/restore 的作用范围与风险。

参考答案

三者作用层面不同，按“影响范围 + 是否改写历史”区分：

1. 仅撤销工作区（未 add）：

  • git restore <file> 或 git checkout -- <file>：丢弃工作区改动，恢复到最近一次提交/暂存状态。安全，不影响历史。

2. 撤销暂存区（已 add 未 commit）：

  • git restore --staged <file> 或 git reset HEAD <file>：把文件移出暂存区，改动仍保留在工作区。

3. 撤销已提交：

  • git reset：移动分支指针，可改写历史。

- --soft：只回退提交，改动留在暂存区。

- --mixed（默认）：回退提交，改动留在工作区。

- --hard：彻底丢弃提交及改动（危险，数据可能丢失）。

- 适合回退自己本地、未推送的提交。

  • git revert <commit>：生成一个新提交来“反向”抵消指定提交的效果，不改写已有历史，对协作安全。适合撤销已推送的公共提交。

结论：本地未推送想抹掉历史用 reset（谨慎 --hard）；已推送/公共分支用 revert。checkout/restore 只动工作区/暂存区，不碰提交历史。
