git cherry-pick 是什么？在什么场景下使用，使用时要注意什么？

中级场景题软件开发工程师(通用)前端开发工程师后端开发工程师DevOps工程师cherry-pick提交移植分支

题目

我想把别的分支上的某一个提交（而不是整个分支）拿到当前分支，该用什么命令？请说明 cherry-pick 的作用、典型用途及潜在风险。

参考答案

作用：git cherry-pick <commit> 把指定提交所引入的变更作为一个新提交应用到当前分支（新 hash，仅复制“改动内容”而非原提交对象）。

典型场景：

  1. 把已修复的某个 bug 提交单独移植到其它发布分支/hotfix 分支。
  2. 误把提交做到错误分支，挑过来后再在原分支 reset 掉。
  3. 选择性复用某次提交，而不想 merge 整条分支。
git checkout release-1.0
git cherry-pick a1b2c3d   # 把该提交的改动应用到当前分支

注意事项 / 风险：

  • cherry-pick 会生成新提交，与原提交 hash 不同；若后续又 merge 原分支，可能产生“重复提交/看似冲突”。
  • 被挑的提交若依赖其前序提交（如改动基于某变量定义），单独挑会冲突或编译失败，此时可能需要连着依赖提交一起挑，或改用 rebase/git rebase --onto。
  • 冲突处理同 merge：--continue / --abort / --skip。
  • 多个提交可 git cherry-pick A..B（左开右闭，不含 A）。
