Redis 常见的缓存淘汰策略有哪些？LRU 和 LFU 有什么区别，分别适合什么场景？

中级简答题淘汰策略LRULFURedis

题目

当 Redis 内存达到 maxmemory 时如何淘汰 key？请说明 noeviction、allkeys-lru、volatile-lru、allkeys-lfu、volatile-ttl 等策略，并对比 LRU 与 LFU。

参考答案

触发：当内存达到 maxmemory，按 maxmemory-policy 淘汰键以腾出空间。

常见策略：

  • noeviction：不淘汰，写操作报错（默认，只读缓存可接受）。
  • allkeys-lru：对所有 key 用 LRU 淘汰。
  • volatile-lru：只对设了 TTL 的 key 用 LRU。
  • allkeys-lfu / volatile-lfu：用 LFU。
  • allkeys-random / volatile-random：随机淘汰。
  • volatile-ttl：优先淘汰剩余 TTL 最短的。

LRU vs LFU：

  • LRU（最近最少使用）：淘汰“最久没被访问”的 key，基于时间局部性。近似实现（Redis 用随机采样近似，非严格链表）。

- 缺点：偶发批量扫描会把热点 key 冲到队尾被误淘汰（“缓存污染”）。

  • LFU（最不经常使用）：记录访问频率，淘汰访问次数最少者。Redis 用带衰减的 counter（概率递增）。

- 优点：抗扫描污染，更贴合真实热度；适合长期热点不均、有突发扫描的场景。

选型：纯最近访问模式用 LRU；存在“一次性大量扫描 + 少量常驻热点”用 LFU；有过期语义且只想淘汰带 TTL 的用 volatile-*。
