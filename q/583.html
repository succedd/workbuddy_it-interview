释放 Redis 分布式锁时直接 `DEL` 有什么风险？如何用 Lua 脚本防止误删别人的锁？

中级故障排查题分布式锁误删防护Lua脚本Redis

题目

线程 A 获取锁后业务执行超时，锁已过期；线程 B 随后拿到锁。此时 A 执行完直接 DEL 会把 B 的锁删掉。请说明风险，并给出正确的释放实现。

参考答案

风险（误删他人锁）：

  1. A 获锁（TTL 30s），业务卡住超过 30s，锁自动过期；
  2. B 获锁（A 不知情）；
  3. A 业务结束，直接 DEL lock → 把 B 的锁删了；
  4. 此时 C 又能获锁，B、C 同时进入临界区 → 互斥失效。

根因：释放时没有校验“这把锁是不是自己加的”。

正确释放（Lua 脚本原子校验）：

if redis.call("get", KEYS[1]) == ARGV[1] then
    return redis.call("del", KEYS[1])
else
    return 0
end
  • 只有 get 到的 value 等于自己当初设的唯一随机值才删除；
  • 用 Lua 保证“判断+删除”原子，避免判断后、删除前锁过期被别人抢走的中间态。
  • Redis 8.4+ 可用等价命令 DELEX key IFEQ <value>。

配套：加锁 value 必须是全局唯一随机串（非固定值），否则仍可能被误删。
