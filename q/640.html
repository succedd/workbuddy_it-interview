CAS 的底层实现原理是什么？它存在哪些问题？

中级简答题Java后端工程师JUCCASUnsafeABAAtomicInteger

题目

承接上题：修复方案里的 AtomicInteger 底层就是 CAS。追问 CAS 是什么、Java 如何实现、有哪些坑。考察点：Unsafe 与原子指令；自旋重试；ABA 问题与 AtomicStampedReference；循环开销与单变量限制。

参考答案

要点一：底层实现

  • CAS（Compare-And-Swap）语义为"当且仅当当前值等于预期值时，才把它更新为新值"，是一个原子操作。
  • Java 侧由 sun.misc.Unsafe 的 compareAndSwapInt/Object/Long（native 方法）表达 CAS 语义，JVM 把这些调用识别为内部函数（intrinsic），最终映射为目标平台处理器支持的原子指令，具体实现依赖 JVM 与 CPU 架构。
  • AtomicInteger 等原子类的 getAndAddInt 就是 do-while 循环不断重试 CAS 直到成功，这就是自旋锁机制。

要点二：三大问题

  • ABA 问题：值从 A 改成 B 又改回 A，CAS 检查时无法感知中途变化。解决办法是加版本号/时间戳，JDK 1.5 起的 AtomicStampedReference 同时比较引用与 stamp 才执行更新。
  • 循环时间长开销大：竞争激烈时自旋长期失败，空耗 CPU。JVM 支持时编译器会在自旋中插入 pause 指令，延迟流水线执行并避免内存顺序冲突清空流水线。
  • 只能保证一个共享变量的原子性：对多个变量无能为力。可用 AtomicReference 把多个变量封装进一个对象做整体 CAS，或退回加锁方案。
