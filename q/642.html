AQS 的核心原理是什么？以 ReentrantLock 和 CountDownLatch 为例说明独占模式与共享模式的区别

高级简答题Java后端工程师JUCAQSReentrantLockCountDownLatchCLH队列

题目

承接上题：CAS 是单点武器，AQS 是用 CAS + volatile state 搭建的同步框架。考察点：volatile int state 的语义多样性；CLH 变体双向队列（自旋+阻塞）；模板方法模式；独占/共享两种模式的典型实现。

参考答案

要点一：三大核心组件

  • state 同步状态：private volatile int state，通过 getState/setState/compareAndSetState（CAS）操作。不同同步器赋予不同含义：ReentrantLock 中代表重入次数（0 为无锁，加锁 +1，解锁 -1）；CountDownLatch 中代表待等待的事件计数；Semaphore 中代表剩余许可证数。
  • CLH 变体等待队列：获取不到资源的线程被封装成 Node 入队。与原始 CLH 锁相比有两点优化：由纯自旋改为"自旋 + 阻塞"（避免长期自旋耗 CPU）；由单向链表改为双向队列（增加 next 指针，便于前驱释放锁后直接唤醒后继节点）。
  • 模板方法模式：AQS 作为抽象框架定义资源获取/释放的通用流程（如 acquire/acquireShared），子类只需重写 tryAcquire/tryRelease/tryAcquireShared 等钩子方法，队列管理、阻塞唤醒等脏活全部由框架完成。

要点二：独占模式 vs 共享模式

  • 独占模式：同一时刻只有一个线程持有资源。ReentrantLock 的 lock() 触发 tryAcquire()，用 CAS 独占 state 并累加实现可重入；只有 unlock() 把 state 减到 0 后其他线程才能获取。
  • 共享模式：允许多个线程同时获取资源。CountDownLatch 的计数归零唤醒所有等待线程；Semaphore 用 CAS 修改 state 控制同时访问的并发数上限。

要点三：设计价值

  • AQS 把"volatile 状态 + CAS + 队列 + 阻塞唤醒"封装成可复用骨架，是 JUC 大部分同步器（ReentrantLock、Semaphore、CountDownLatch、CyclicBarrier 内部的 ReentrantLock+Condition）的共同基座，回答并发问题时能自底向上串起 volatile→CAS→AQS 整条链。
