DNS 解析中的递归查询与迭代查询有什么区别？以解析 www.server.com 为例说明本地 DNS 服务器的角色

初级简答题后端架构师Go后端工程师后端开发工程师gRPCProtobufHTTP2RPC

题目

追问链起点：从"DNS 解析流程"深入到查询模式的本质。考察点：递归查询（替你问到底）与迭代查询（只指路不带路）的区别；本地 DNS 在两种模式间扮演的角色；根/顶级/权威三级服务器的分工。

参考答案

要点一：两种查询模式的区别

  • 递归查询：客户端只发一次请求，由被请求方（本地 DNS 服务器）负责一路查到底，最终把结果返回给客户端。客户端到本地 DNS 之间通常是递归查询。
  • 迭代查询：被请求方不替你查到底，只返回它认为"下一步该去问谁"的地址，由请求方自己继续追问。本地 DNS 到根/顶级/权威服务器之间通常是迭代查询——"只指路不带路"。

要点二：www.server.com 的完整解析流程

  • 1) 客户端把 www.server.com 的查询发给本地 DNS（TCP/IP 设置中配置的 DNS 服务器）；本地 DNS 缓存未命中后开始逐级查询。
  • 2) 本地 DNS 问根 DNS 服务器：根不直接给出 IP，而是说".com 归顶级域服务器管"并返回其地址。
  • 3) 本地 DNS 问 .com 顶级域服务器：返回负责 server.com 区域的权威 DNS 服务器地址。
  • 4) 本地 DNS 问权威 DNS 服务器：权威服务器是域名解析结果的原出处（"我的域名我做主"），查询后把 IP 返回给本地 DNS。
  • 5) 本地 DNS 把 IP 返回客户端并写入缓存，客户端拿到 IP 后与目标建立连接。

要点三：角色总结

  • 同一次解析中查询模式是混合的：客户端→本地 DNS 是递归，本地 DNS→三级服务器是迭代。
  • 本地 DNS（运营商或公共 DNS）是缓存与递归的核心枢纽，它的缓存命中率直接决定绝大多数解析的速度。
