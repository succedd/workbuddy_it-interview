JVM 如何判断一个对象已经「死亡」？引用计数法为什么没有被 Java 采用？

中级简答题Java开发工程师Java后端工程师JVMGC可达性分析引用计数

题目

追问链起点。考察点：引用计数法的实现与致命缺陷；可达性分析的基本思路；Java 的四种引用强度对对象生命周期的影响。

参考答案

要点一：引用计数法及其缺陷

  • 做法：每个对象维护一个引用计数器，被引用时 +1，引用失效时 -1，计数为 0 即认为可回收。
  • 优点：原理简单、判定效率高，Python、Objective-C 等都采用过。
  • 致命缺陷：无法解决循环引用。对象 A 持有 B、B 持有 A，两者都不再被外部使用，但计数恒为 1，永远无法回收，从而造成内存泄漏。此外计数的加解密伴随每一次赋值，额外开销也不小。
  • 正因如此，主流 Java 虚拟机都没有采用引用计数法来管理内存。

要点二：可达性分析（Java 采用）

  • 思路：以一系列称为 GC Roots 的根对象为起点，按引用关系向下搜索，走过的路径称为「引用链」。
  • 某个对象到 GC Roots 之间没有任何引用链相连（即从根出发不可达），则证明该对象不可能再被使用，可被回收。
  • 它天然解决了循环引用问题：两个互相引用但整体不可达的对象，会被一并判定为可回收。

要点三：Java 的四种引用强度

  • 强引用：Object o = new Object()，只要强引用存在，对象永远不会被回收，内存不足时宁可抛 OOM。
  • 软引用（SoftReference）：内存不足（即将 OOM）时会被回收，适合做内存敏感的缓存。
  • 弱引用（WeakReference）：只要发生 GC 就会被回收，与内存是否充足无关，典型应用是 WeakHashMap、ThreadLocalMap 的 key。
  • 虚引用（PhantomReference）：无法通过它取得对象实例，唯一作用是在对象被回收时收到系统通知，用于管理堆外内存（如 DirectByteBuffer 的 Cleaner）。

要点四：面试答题建议

  • 先答「可达性分析」，再说「引用计数法不采用是因为循环引用」，最后补一句「可达性分析还要结合四种引用强度综合判断」，层次就完整了。
