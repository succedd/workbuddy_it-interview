Minor GC、Major GC、Full GC 有什么区别？分别在什么情况下触发？

中级简答题LLM应用开发工程师AI应用开发工程师AI Agent开发工程师LangChainChainToolMemory

题目

追问链第三问。考察点：部分收集与整堆收集的划分；新生代 Eden 不足触发 Minor GC；晋升与空间分配担保；System.gc() 只是建议。

参考答案

要点一：概念划分

  • HotSpot 把 GC 分为两大类：部分收集（Partial GC） 与 整堆收集（Full GC）。

- Minor GC / Young GC：只收集新生代（Eden + Survivor）。

- Major GC / Old GC：只收集老年代，目前只有 CMS 有单独收集老年代的行为。

- Mixed GC：收集整个新生代 + 部分老年代，只有 G1 有此模式。

- Full GC：收集整个 Java 堆和方法区。

  • 注意：业界对 Major GC 的叫法并不统一，很多资料把 Major GC 等同于 Full GC，面试时最好先说明自己按哪套定义回答。

要点二：Minor GC 的触发条件

  • Eden 区空间不足时触发。新对象优先在 Eden 分配，放不下就发生一次 Minor GC，存活对象复制到 Survivor 并年龄 +1。
  • 特点：非常频繁、速度较快，因为新生代对象大多朝生夕灭，复制成本很低。
  • 会引发 Stop The World，但停顿通常很短。

要点三：对象进入老年代的三条路径

  • 年龄阈值：对象在 Survivor 中每熬过一次 Minor GC 年龄 +1，超过 -XX:MaxTenuringThreshold（默认 15）晋升老年代。
  • 动态年龄判定：Survivor 中同龄对象大小总和超过 Survivor 空间的一半，则年龄大于等于该年龄的对象直接晋升，无需等到阈值。
  • 大对象直接进入：超过 -XX:PretenureSizeThreshold 的大对象（如长数组、大字符串）直接进入老年代，避免 Eden 与两个 Survivor 之间来回复制的高昂开销。

要点四：Full GC 的触发条件

  • 老年代空间不足（晋升对象放不下）；
  • 方法区 / 元空间不足；
  • 空间分配担保失败：Minor GC 前 JVM 检查老年代最大可用连续空间是否大于新生代所有对象总大小（或历次晋升平均大小），不满足则先触发一次 Full GC 腾空间；
  • 调用 System.gc()——只是建议，是否执行由虚拟机决定（可用 -XX:+DisableExplicitGC 禁止）。
  • 特点：Full GC 停顿时间最长，是线上调优要重点消除的对象（通常通过合理设置堆大小、选择合适的收集器让对象尽量在新生代回收掉）。
