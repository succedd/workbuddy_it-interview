CMS 与 G1 垃圾收集器的工作流程和适用场景有什么区别？

高级简答题模型部署工程师MLOps工程师深度学习工程师模型量化剪枝ONNX推理优化

题目

追问链第四问。考察点：CMS 的四步与「低停顿但碎片化」的取舍；G1 的 Region 化与可预测停顿模型；两者的共同点与 G1 的替代关系。

参考答案

要点一：CMS（Concurrent Mark Sweep）——追求低停顿

  • 目标：获取最短回收停顿时间，适合重视响应速度的互联网应用。
  • 工作流程四步：

1. 初始标记：只标记 GC Roots 能直接关联到的对象，需要 STW，但极快。

2. 并发标记：从初始标记对象出发遍历整个对象图，与用户线程并发，耗时最长但不阻塞业务。

3. 重新标记：修正并发标记期间因用户线程继续运行而产生的变动，需要 STW，时间略长于初始标记。

4. 并发清除：清理死亡对象，与用户线程并发。

  • 主要缺点：

- 标记-清除算法产生内存碎片，碎片过多会触发 Full GC 且退化为 Serial 单线程收集；

- 并发阶段占用 CPU 资源，降低吞吐量；

- 无法处理「浮动垃圾」，并发期间还需预留空间，若预留不足会出现 Concurrent Mode Failure。

要点二：G1（Garbage First）——可预测停顿模型

  • 目标：在延迟可控的前提下获得尽可能高的吞吐量，是 JDK 9 起的默认收集器。
  • 核心设计：

- 把整堆划分为多个大小相等的 Region（1MB~32MB，2 的幂），每个 Region 可动态扮演 Eden / Survivor / Old / Humongous 角色，不再要求内存物理连续。

- 维护每个 Region 的回收价值（能回收多少空间 + 预计耗时），按 -XX:MaxGCPauseMillis（默认 200ms）选择收益最高的若干个 Region 回收，即 Garbage First 名字的由来。

- 整体看是标记-整理，局部（Region 之间）看是标记-复制，因此基本不产生内存碎片。

- 用 Remembered Set 记录跨 Region 引用，避免全堆扫描。

  • 工作流程：初始标记（STW）→ 并发标记 → 最终标记（STW）→ 筛选回收（Evacuation，STW，按价值排序回收选定 Region）。

要点三：适用场景对比

  • CMS：堆较小（如 4GB 以内）、要求极低停顿、CPU 资源充足；适合老年代对象生命周期长、回收不频繁的场景。JDK 9 起已被标记废弃，JDK 14 中被移除。
  • G1：堆较大（6GB 以上）、希望停顿时间可预测、同时兼顾吞吐；大堆下优势明显，是目前服务端主流选择。
  • 更低延迟场景（要求亚毫秒级）可了解 ZGC / Shenandoah，它们通过染色指针与读屏障把停顿控制到与堆大小几乎无关。

要点四：二者共同点

  • 都存在并发标记阶段（与用户线程一起跑）；
  • 初始/重新（最终）标记阶段都需要 STW；
  • 都属于「低延迟」取向的收集器，与「高吞吐」取向的 Parallel Scavenge / Parallel Old 形成对比。
