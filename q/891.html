雪花算法在生产中生成了重复/负数 ID，定位为「时钟回拨」导致。如何排查与兜底？

中级故障排查题Java后端工程师雪花算法时钟回拨分布式ID容错

题目

考察雪花算法的时钟回拨问题。

参考答案

根因：雪花 ID 高位是 当前时间戳-epoch，若机器时钟往后回拨（NTP 校正、虚拟机迁移），会生成与历史相同时间戳+同序列的重复 ID，甚至时间戳变负→ID 变负。

排查：看 ID 解析出的时间戳是否 < 上一次生成的时间戳；查机器 ntpdate/chrony 日志确认是否有回拨事件。

兜底方案：

  • 等待追平：检测到回拨时，短暂自旋/睡眠直到时钟追上上次时间（仅适合小幅度回拨）。
  • 回拨计数：用序列号借位或扩展位记录回拨次数，保证回拨期间不重复。
  • 拒绝服务+告警：大幅回拨直接抛错并告警，由人工介入，比生成脏 ID 安全。
  • workerId 隔离：时钟不可靠的机器分配独立 workerId，避免回拨影响其他节点。根本解是用可靠时钟源（chrony）+ 禁止大步长 NTP 跳跃。
