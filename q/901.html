深度分页（LIMIT 1000000, 10）为什么慢？如何优化？

中级简答题后端开发工程师数据库工程师Java后端工程师Java开发工程师MySQL深度分页SQL优化

题目

请解释 LIMIT 大偏移量下 MySQL 的执行过程与性能瓶颈，并给出几种可行的优化方案。

参考答案

慢的原因：LIMIT 1000000,10 并不是直接跳到第 1000001 行——存储引擎仍要按索引顺序取出并丢弃前 100 万条记录（Server 层逐条判断、回表后再丢弃），实际只返回 10 条。偏移量越大，无效工作量越大。

优化方案：

  1. 游标/续页法（最优）：记录上一页最后一条的排序键，下页改为

WHERE id > #{lastId} ORDER BY id LIMIT 10。利用索引定位直接跳到起点，任何页都是常数代价。要求排序键单调且不支持随机跳页。

  1. 子查询/延迟关联：先在覆盖索引里拿到目标主键，再回表取整行：

SELECT * FROM t JOIN (SELECT id FROM t WHERE cond ORDER BY id LIMIT 1000000,10) tmp USING(id)。把 100 万次回表压缩为 10 次。

  1. 业务约束：限制最大翻页深度（如只允许前 500 页）、提供搜索/筛选条件减少无效数据量。
  2. 数据量特别大且分析型查询，考虑离线同步到 ES/ClickHouse 处理。
