Redis 为什么这么快？

初级简答题Java开发工程师后端开发工程师Java后端工程师后端架构师Redis性能单线程

题目

从内存、数据结构、线程模型、IO 等角度说明 Redis 高性能的原因。

参考答案

  1. 纯内存操作：数据全在内存，读写比磁盘数据库快几个数量级（内存随机访问约 100ns 级，磁盘毫秒级）。
  2. 高效数据结构：针对不同场景定制——SDS 动态字符串（O(1) 取长度）、ziplist/listpack 压缩列表（小数据省内存）、skiplist 跳表（ZSet 范围查询 O(logN)）、intset、quicklist 等；多数命令 O(1)~O(logN)。
  3. 单线程无锁竞争（指命令执行线程）：没有多线程上下文切换和锁开销，实现简单且可预测。
  4. IO 多路复用：epoll 单线程监听大量连接，Redis 6.0 后网络读写甚至并行化（多线程 IO），但命令执行仍是单线程。
  5. 通信协议 RESP 简单：文本协议解析开销极小。
追问点：单线程快的前提是"每条命令都足够快"——所以有大 key（如百万元素的集合）或 O(N) 命令（KEYS、HGETALL 大哈希）时要拆分，否则会阻塞整个实例。
