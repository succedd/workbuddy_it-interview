什么是零拷贝（zero-copy）？sendfile 如何提升传输性能？

高级简答题后端架构师Go后端工程师后端开发工程师系统运维工程师操作系统零拷贝IO

题目

请对比传统 read+write 传输文件的多次拷贝与上下文切换，说明 mmap、sendfile 等零拷贝手段的优化原理。

参考答案

传统方式把文件从磁盘发到网卡要经历：DMA 拷贝到内核缓冲区 → CPU 拷贝到用户缓冲区（read 返回）→ CPU 拷贝到 socket 缓冲区（write）→ DMA 拷贝到网卡。4 次拷贝、4 次用户/内核态切换，其中两次纯 CPU 拷贝毫无必要——数据根本不需要进用户空间。

优化手段：

  1. sendfile（Linux 2.1+）：数据全程留在内核态——内核缓冲区直接拷到 socket 缓冲区（或 DMA gather 直接从内核缓冲区送网卡，零 CPU 拷贝），切换从 4 次降到 2 次。Kafka 高吞吐、Nginx sendfile on 都是它。
  2. mmap+write：把文件映射进用户地址空间，省掉"内核→用户"的一次 CPU 拷贝，适合需要修改数据的场景（RocketMQ 存储基于 mmap）。
  3. splice：利用管道在两个 fd 间移动数据，不经过用户态。

收益本质：减少不必要的 CPU 拷贝与态切换，把 CPU 留给业务逻辑——这正是 Kafka 单机百万级 TPS 的底层秘诀之一。
