用 Proxy 给配置对象加「只读 + 访问日志」拦截时遇到四个诡异问题（JSON.stringify 没进 get 陷阱、proxy 与 target 判等不等、revoke 后访问报错、代理 Map 失败），请逐一分析成因并修复。

题目

考察点：Proxy 的代理身份、this 绑定陷阱、Proxy.revocable、对内置对象（Map/Set）代理的坑。这是 ES6 元编程的集大成追问，综合前面对象/函数知识。

参考答案

现象：套了 Proxy 做只读+日志后，① JSON.stringify(proxy) 似乎没走 get 陷阱；② proxy === target 为 false；③ 调 revoke() 后再访问代理直接抛 TypeError；④ 代理一个 Map 报错。

要点与修复：

  • Proxy 是「另一个对象」：它不是 target 的壳，而是拥有独立身份的代理，所以 proxy === target 永远为 false；JSON.stringify 确实会对代理调用 get / ownKeys / getOwnPropertyDescriptor 等陷阱——若你只拦了 get 而没在 ownKeys / getOwnPropertyDescriptor 里正确转发，序列化就「看起来没进陷阱」。统一用 Reflect.* 在陷阱里转发可避免遗漏。
  • this 绑定陷阱：当代理对象的方法（普通函数）内部用 this 访问私有字段时，this 会是 proxy 而非原始对象，导致访问私有成员失败；修复是在陷阱里把 this 重定向回 target，例如 Reflect.get(target, key, target)（注意第三个参数 receiver 传 target）。
  • revocable 误用：Proxy.revocable() 返回的 revoke() 一旦调用，代理的所有后续操作都会抛 TypeError；应确保只在真正要「销毁」代理时调用，且调用后不再访问。
  • 内置对象（Map/Set/Date…）带内部槽：直接 new Proxy(map, handler) 转发会失败，因为这些对象依赖语言内部槽、代理读不到；必须手动在 get 陷阱里把方法 this 绑回原始对象（如 const v = Reflect.get(target, key); return typeof v === 'function' ? v.bind(target) : v;）。

一句话：代理一切皆用 Reflect 转发，涉及 this 的方法在陷阱内 bind(target)，原生内置对象单独处理内部槽，revoke 调用前加守卫。
