在工程里如何让大模型稳定输出可解析的 JSON（结构化输出）？请说明 Prompt 约束、厂商能力与代码兜底三层做法。

中级场景题算法工程师后端开发工程师Prompt Engineering结构化输出JSON函数调用tool use

题目

考察点：结构化输出约束的工程落地（JSON mode / Structured Outputs / 函数调用），以及代码侧兜底解析。这是把 LLM 接入系统的关键。

参考答案

要点：

  • 为什么约束格式：下游系统只认可解析结果（分类、抽取、工具调用），自由文本难解析；用 JSON / 固定 schema 最稳。
  • Prompt 层：明确「只返回 JSON，字段为 {…}」，给出示例，禁止输出多余解释文字。
  • 厂商能力层（优先）：直接用 Structured Outputs / JSON mode（如 OpenAI structured outputs 按 schema 强制约束）或 函数调用（tool use）——把要抽取的结构定义为工具参数 schema，让模型以「调用函数」形式返回，比纯文本 JSON 可靠得多。
  • 代码兜底层：去掉 ```json 标记、捕获解析异常、字段缺失时重试或要求模型修正；校验字段类型与必填；设足 max_tokens 防止截断。
  • 经验：不要只靠 prompt 说「请输出 JSON」就信任结果，必须「厂商 schema 约束 + 代码校验」双保险。
