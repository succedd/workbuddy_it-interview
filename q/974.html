以下关于 Prompt Engineering 的说法，哪一项是正确的？

中级单选题算法工程师后端开发工程师Prompt Engineering少样本思维链结构化输出提示注入单选

题目

考察点：对少样本、思维链、结构化输出、提示注入防护四类常见认知误区的辨别。单选题收尾，巩固整条追问链。

参考答案

题目：

A. 所有任务都该加 few-shot 示例，示例越多越好

B. 思维链（CoT）对数学/多步推理任务提升明显，但对纯事实抽取任务未必有用

C. 开启 JSON mode 后就可以完全信任模型输出的字段类型，无需代码校验

D. 防止提示注入只需把指令写得更长更详细即可

答案：B。

要点：

  • A 错：示例质量 > 数量，简单任务零样本更好，过多示例拖慢且可能引入偏见。
  • B 对：CoT 主要增益在推理/多步逻辑任务；事实抽取/格式转换类任务加 CoT 收益有限甚至更慢。
  • C 错：JSON mode 仍可能截断或漏字段，代码侧必须校验类型与必填、做兜底解析。
  • D 错：注入防护靠「指令与数据隔离 + 护栏 + 输出校验」，不是靠把 system prompt 写长。
