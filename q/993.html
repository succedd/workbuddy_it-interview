DataX 同步 MySQL 到 Hive 任务很慢或 OOM，你怎么调优？

高级开放讨论题大数据开发工程师数据仓库工程师DataX调优splitPk数据同步

题目

考察点：并发切分、JVM 内存、限速参数、分库分表读取。

参考答案

要点：

  • 提并发：job.setting.speed 之外，关键是 reader 的 splitPk（按主键哈希把一张表切成多个 Task 并行读）——没配 splitPk 就只有单 channel 串行，这是「很慢」的头号原因。channel 数与 splitPk 分片数匹配（一般 4~16 channel）。
  • JVM 调优：DataX 进程默认内存偏小，大字段/大并发会 OOM——启动脚本调 -Xms/-Xmx（如 4~8G），并控制单 channel 的 batchSize（writer 攒批条数）与 byte/record 限速，内存占用≈batchSize×行宽。
  • 源库保护：错峰同步、只同步增量（where update_time >= ... 或用 Binlog 方案替代）、slave 库读取、querySql 精确投影字段避免 SELECT *。
  • 写入侧：Hive writer 用 textfile 中转再 INSERT OVERWRITE 转正式表格式，或直接 orc；分区表按分区写，避免小文件爆炸（配合后续 merge）。
  • 观测：DataX 自带流量/脏数据统计，先看瓶颈在读端还是写端再对症下药。
